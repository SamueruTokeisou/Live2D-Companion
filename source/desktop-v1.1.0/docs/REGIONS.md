# 热区（Regions）——现行逻辑与动态热区可行性

> 面向：开新会话专攻热区的人（未来的我）。
> 现状确认时间：2026-11-03。相关代码、探针、实测数据都在这里，不用再从零翻。

---

## 0. 一句话结论

现在能做、也**已经**在做的“动态热区”只有四块：**左右脸、额头、左右手、长裙**（按蒙皮顶点实时算，80ms 一拍）。
身体段（头/胸/腰/裙摆/腿/脚/胯/尾巴）是**播种一次的快照**，只在换装/换体型时重铺。

**动态身体段是可行的**，实测一次全量收集 **1.3–1.8ms**（28 个部件），
每 100ms 段边缘只移动 **2–6px**（尾巴 10–15px），加个死区/低通就不会抖。
但**不能**直接把“部件组包围盒”当身体段用：胸/腰/裙的组包围盒会互相大面积重叠（实测腰段差 804px），
必须**每拍重跑一次锚点推导**（`neckY / chestY / waistY / skirtBottom / footY`），再切段矩形 —— 那步是纯算术，几乎不花钱。

## 1. 坐标系与数据模型

- 坐标空间：**模型画布像素**（本模型 3749 × 7697），原点左上、y 向上增大方向与 `getDrawableVertices()` 一致。
  屏幕坐标换算走 `viewport.clientToModel()` / `modelToScreen()`，热区本身**不随窗口缩放变化**。
- 一条热区（`createRegionStore` 里的对象）：

| 字段 | 含义 | 说明 |
|---|---|---|
| `id` | 唯一 id | `r` + 时间戳；存档时保留 |
| `name` | 名字 | **语义键**：反应表、状态联动（长裙/胸/腿）、诊断全按名字匹配 |
| `points` | 多边形 `[[x,y],…]` | 支持任意多边形，实际常用矩形/椭圆分段/凸包 |
| `holes` | 洞的数组 | 尾巴用：把被身体段盖住的部分挖掉 |
| `z` | 层级 | **大的优先命中**；相同 z 时后加入的优先（后画 = 更靠前） |
| `reaction` | `{tap:{…}, pet:{…}}` | 反应表；`toggle` / `expr[]` 两种语义 |
| `disabled` | 临时停用 | 长裙时腿、抚胸时胸；不参与命中，但几何/反应都留着 |
| `v` | 迁移版本 | 见 §4.3 |

## 2. 三类来源（谁在改热区）

### 2.1 播种型（身体段）—— `seedRegions()`

文件：`src/stage/regions/zones.js`。一次扫描 715 个 drawable，**先按部件名筛组、再读顶点**
（顺序反了每次都要拉全模型顶点，实测单次 ~99ms、fps 掉到 26.9 —— 别再犯）。

分组表（`SEED_GROUPS`）：

| 组 | 部件名关键字 |
|---|---|
| head | 头/脸/脸底/五官/脖子/耳朵/发饰/女仆发饰/前发/眉毛/眼眶/眼球/眼白/嘴/鼻子 |
| chest | 胸衣/胸/领子/肩膀花边-变q |
| waist | 腰部衣服 |
| skirt | 短裙/长裙/短裙后/长裙后/长裙蝴蝶结/身后蝴蝶结 |
| legs | 腿/左腿/右腿 |
| tail | 尾巴/狗尾草 |

**段不是按组包围盒切的**，而是先求锚点、再切竖向条带（这就是关键）：

```
neckY     = head.maxY                      // 脖子下缘
chestY    = chest.maxY                     // 胸衣下缘
waistY    = skirt.minY + 裙高 × 0.45        // 腰/裙分界（只认「短裙/短裙后」，长裙会把上缘拉到胸口）
skirtBottom = skirt.maxY
footY     = legs.maxY - 腿高 × 0.105        // 鞋口
band(头)   = [body.minY, neckY],   z=7
band(胸)   = [neckY, chestY],      z=6
band(腰)   = [chestY, waistY],     z=5
band(裙摆) = [waistY, skirtBottom], z=4
band(腿)   = [skirtBottom, footY], z=3
band(脚)   = [footY, legs.maxY],   z=3
```

额外两块：

- **胯**：由锚点推导（不再写死 41.5%–50.5%）。纵向 `chestY + (waistY-chestY)*0.45 → waistY + (skirtBottom-waistY)*0.33`，
  横向按腰宽收窄 35%（上限 11% 画布宽），`z=6`。
- **尾巴**：所有 tail 组顶点的凸包（`simplify(convexHull, 12)`），`z=1`，
  并把与身体段相交的矩形作为 `holes` 挖掉。

### 2.2 跟随型（网格驱动）—— 80ms 心跳

文件：同上的三个读取器 + `app/renderer.js` 的 `startFaceRegionTracking()`。

| 热区 | 读取器 | 算法 | z |
|---|---|---|---|
| 左脸 / 右脸 | `createFaceZoneReader` | 「脸/脸底」部件包围盒 → 眼睛以下椭圆，竖着切两半，各 14 段 | 8 |
| 额头 | 同上 `readForehead()` | 脸包围盒上半段矩形（3%–44% 高），只处理 tap | 9 |
| 左手 / 右手 | `createHandZoneReader` | 「手/手指」部件全部顶点 → 按整体包围盒中线切两簇，各自包围盒 +8% 余量 | 8 |
| 长裙 | `longSkirtRegion()` | 长裙三组部件顶点凸包；短裙态这些图层 opacity≈0 → 返回 null | 4 |

要点（都踩过）：

- 索引表按 `drawableCount/partCount` 签名缓存，只在换装/换模型时重扫。
- 手在抬手时是**换图**：读取器跟不到新网格，所以 `stretchHandZones()` 按姿势状态把热区“铺过去”
  （竖食指 → 沿手臂延到头部下沿、z 提到 9；抚胸 → 朝身体中线铺开）。
- 只剩一只手可见时，读取器会把它切成两块（手指/手掌）→ 中心距过近就合并。
- 左右手按屏幕左右重新指派，别信读取器的名字（抬手会调换）。
- 脸/手/额头的重算是 80ms 一拍，不是每帧：每帧读顶点会拖死帧率（历史事故）。

### 2.3 状态联动（几何之外）

| 联动 | 触发 | 效果 | 代码 |
|---|---|---|---|
| 长裙 ↔ 腿 | `skirtIsLong()`（看层里有没有「裙子切换」，**不能读参数**，表达式参数每帧被基线重置） | 腿 `disabled`，长裙热区长出/停用 | `syncSkirtZone()` |
| 抚胸 ↔ 胸 | `poses.state().hands.right === '抚胸'` | 胸 `disabled` | `syncChestZone()`（1s 心跳） |
| 抬手 | 姿势状态 | 手区延展 + z 调整 | `stretchHandZones()` |
| 尾巴藏起来 | 层里有「尾巴开关」 | 画一个恢复按钮（不是热区） | `syncTailRestore()` |
| 额头 | — | 只管 tap，抚摸/拖动按「头」处理 | `onEvent` 里改名 |

## 3. 命中与手势规则

### 3.1 命中（`store.hit`）

```
遍历全部热区 → 跳过 disabled → pointInPolygon(points) → 排除 holes → 取 z 最大（同 z 取后加入）
```

按下时再过一道**透明像素门控**（SPEC §5）：`stage.sampleAlpha()`，alpha ≤ 16 视为穿透。
例外：「左手/右手」跳过门控（手指边缘透明像素多，否则点不到）。

### 3.2 手势（`src/stage/regions/input.js`）

阈值按**画布宽度比例**给（与窗口缩放、模型分辨率无关；曾经按绝对像素定，屏幕动 8px 就被判成拖动）：

| 手势 | 判定 |
|---|---|
| `tap` | 位移 ≤ 2% 画布宽 且 ≤ 420ms |
| `pet` | 按住滑动，每 3% 宽上报一次；连续抚摸 ≥3 次也归为 pet |
| `drag` | 位移 > 8% 宽，且**不是从区外滑进来的** |

起手规则：允许在热区外起手，滑进热区才采纳；已采纳后只允许**更高 z** 的热区接管；
换目标时抚摸步数从头计。起手范围 = 应用窗口边界（窗口贴着角色，窗外事件根本进不来）。

### 3.3 反应（`src/stage/reactions.js` + `DEFAULT_REACTIONS`）

```
region.reaction[kind]（用户配置优先） → 否则 DEFAULT_REACTIONS[name][kind]
toggle 型：独立 source 层，再点同一个热区才收回（长期状态：换装/脱鞋/尾巴/胸口衣服）
expr[] 型：一组临时表情，6s 后自动撤（同一时刻只有一组）
```

## 4. 更新策略与存档

### 4.1 什么时候重铺

- **身体段**：`zoneMaterialSig()` 变了才重铺 —— 签名 = `Clothes1..5` 五个参数值 + 层里是否有
  `裙子切换 / 脱鞋 / 尾巴开关 / 胸口衣服 / 体型*`。1s 轮询一次。为什么不用定时重铺：
  待机时头会晃，同一份热区两次采样能漂 89px，定时重铺等于让热区跟着呼吸抖、还不停写盘。
- **脸/额头/手**：80ms 心跳，只改内存不写盘。
- **长裙**：跟身体段一起刷新（`syncSkirtZone`）。
- **拉条/换装**：`scheduleZoneRefresh(400)` 防抖 + 事后校验几次。

### 4.2 写盘与居中

- 几何变化超过 0.6px（`samePts`）才标脏并写盘，避免待机微动刷盘。
- 只有**体型/裙装**变化才重算窗口居中（`fitKey`），否则窗口会跟着呼吸抽动。

### 4.3 迁移

`ZONE_MIGRATIONS`：名字集合 + 版本号，旧版本删掉重建（`faceRegions` v3、`handReader` v1、`forehead` v1）。
迁移失败必须 `console.warn` 并**保留旧热区**（以前 catch 成空数组，热区直接消失且无痕迹）。
旧档案里 `preset:pose:护胯` 之类在编辑台侧清理。

## 5. 允许的逻辑（红线）

1. **平铺 + z，没有父子层级**。同 z 靠“后加入者优先”兜底；需要覆盖关系就显式给 z。
2. **热区只决定“点到了谁”，不决定“演什么”**。反应表、气泡、情绪全在上层。
3. **透明处必须穿透**：任何新热区都要过 alpha 门控（手部例外）。宁可点不到，也不能挡住桌面。
4. **命中路径不许读顶点**：`store.hit` 必须是纯几何；顶点读取只允许在心跳里批量做。
5. **拖动/捏脸期间不许重铺**：几何在交互中变化会让点击“跳走”。当前靠 `scheduleZoneRefresh` 防抖 +
   身体段只在材料签名变化时重铺；如果做动态热区，必须显式加“交互期间冻结”。
6. **几何抖动阈值 0.6px**，低于它不写盘、不重算居中。
7. **同一部位被多块热区覆盖时必须能收敛**：手部“切成两块”用距离合并，左右手用上一帧连续性校正。
8. **热区名是语义键**：改名 = 断反应表/断联动。新增热区要同时给 `DEFAULT_REACTIONS` 条目。
9. **性能预算**：全量收集 ≤ 2ms/次，心跳 ≥ 80ms；命中 ≤ 20 个多边形。
10. **可编辑**：store 支持用户改几何；自动重铺只动“自己生成的那几块”，不碰用户手画的。

## 6. 动态热区：可行性与实测

### 6.1 已有实现（拿来做样板）

脸/额头/手/长裙已经是“完全动态”的：
`createFaceZoneReader` / `createHandZoneReader` / `longSkirtRegion` + 80ms 心跳。
它们的共同套路 = **索引表缓存 + 每拍只读那几十个 drawable 的顶点 + 输出多边形**。

### 6.2 实测数据（2026-11-03，本机，模型 715 drawable / 148 部件）

原型：`bandBoxes()`（`src/stage/regions/zones.js`）+ `__probe.dynZones()` + `tools/lab/dyn-zones.mjs`。
一次调用 = 全量扫描 + 各段包围盒（这就是“每拍重算”的成本上限）。

| 指标 | 实测 |
|---|---|
| 单次收集耗时（28 个部件） | min 1.3 / 中位 1.5 / p90 1.7 / max 1.8 ms |
| 段边缘移动/100ms（待机，关掉待机动作后 25 次采样） | 头 4.3 / 胸 4.4 / 腰 2.3 / 裙摆 2.1 / 腿 2.0 / 尾巴 **10.1** px |
| 单拍最大跳变 | 头 6.2 / 胸 6.5 / 腰 3.5 / 裙摆 2.9 / 腿 2.7 / 尾巴 **15.1** px |
| 静置时动态盒 vs 存档静态盒 | 头 -6px、尾巴 -38px（刚性部位基本重合） |

**关键反例**（必须知道）：把“部件组包围盒”直接当身体段用会错得离谱 ——

| 段 | 组包围盒 vs 存档段（dx0, dy0, dx1, dy1） |
|---|---|
| 胸 | -12, **-107**, -12, -5 |
| 腰 | -9, **-804**, -8, **-497** |
| 裙摆 | -1, **-672**, +5, +2 |
| 腿 | -5, **-1236**, -4, **+684** |

原因：组包围盒是“衣服/皮肤的多边形外接框”，罩住的范围远超“竖向条带”的语义
（腰部衣服的盒子能盖到胸口和裙摆）。所以动态身体段**必须重跑锚点推导**（§2.1 那五条），
不能拿组盒子直接切。

### 6.3 四条路线

| 路线 | 做法 | 成本 | 风险 | 评价 |
|---|---|---|---|---|
| **A. 锚点重推导**（推荐） | 80–100ms 跑一次 `collectGeometry` → 重算 `neckY/chestY/waistY/skirtBottom/footY` → 切段矩形 + 胯/尾巴 | 1.5ms/拍，摊到每帧 <1% | 段边缘 2–6px 抖动（尾巴 10–15px） | 语义不变、改动最小，优先做 |
| **B. 凸包化** | 腰/腿/胯改成组顶点凸包（或 alpha 形状简化） | 凸包 O(n log n) + 点多 → 命中变慢 | 多边形重叠更严重、点太多 | 只对“胯/尾巴”这种形状不规则的有意义 |
| **C. 像素掩码（id-buffer）** | 渲染一遍部件 id 色图，命中 = 采样该像素得到部件 → 段 | 需自定义 pass / 每帧一次额外渲染 | pixi8 多 pass 与物理链；读回 1–3ms | 精度最高，建议后置，先不做 |
| **D. 姿势模板插值** | 已知姿势（垂手/竖食指/抚胸/举手/狗尾草）→ 手区在几套模板间插值 | 几乎为 0 | 只覆盖已知姿势 | 已在 `stretchHandZones` 里用了雏形，继续用它 |

**推荐组合：A（身体段跟随）+ D（手部姿势模板）+ 现有 2.2（脸/手/长裙实测跟随）。**

### 6.4 落地要点（给实现者的坑）

1. **抖动**：段边缘每 100ms 变化 2–6px，直接重铺会让命中“呼吸”。加：
   - 死区：`|新值-旧值| < 6px` 不更新；
   - 或 EMA（`smooth(prev, next, 0.25)`）；
   - 尾巴单独放宽到 12–15px（它本来就该晃）。
2. **冻结**：拖动窗口、捏脸、抚摸期间不重铺（复用 `state.windowDragging` / `regionInput.pressed` 做门控）。
3. **成本分摊**：1.5ms 单拍在 120Hz（8.3ms）下是 18%，别和物理/绘制同一帧挤。
   可以拆成两拍轮流（`head/chest/waist` 一拍、`skirt/legs/tail` 一拍，各 ~0.7ms），
   或把 `collectGeometry` 与现有的 face/hand 心跳合并成**一次**扫描（现在各扫各的，有重复）。
4. **换装/体型**：锚点重推导天然会跟着变（Clothes1..5 变 → 段位置变），
   但 `zoneMaterialSig` 那套“变了才重铺”可以退役一半（改为“动态跟随 + 存档只做兜底”）。
5. **存档策略**：动态热区不要再每拍写盘。改成“退出/换装时把最后一版几何存下来”，
   下次启动先用存档、模型加载完再切到动态。
6. **命中与渲染不同步**：几何是上一拍（≤100ms）的。点击瞬间想要精确，可以：
   - 按下时强制算一次（`collectGeometry` 1.5ms，低频可接受）；
   - 或者维持现状（100ms 内人的手几乎不动，误差 < 6px）。
7. **命名/反应表不变**：动态只改 `points/holes`，`id/name/reaction/z` 不动，上层零改动。
8. **编辑台**：编辑台预览是另一具实例，`localizeRegions()` 已经用自己网格重铺身体段。
   动态化后编辑台也要跟着跑（否则两边不一致），建议把“段推导”抽成共用函数。

### 6.5 验证方法

| 5 | 尾巴/胯用凸包跟随（可选） | 摸尾巴边缘命中正确 |
| 6 | 编辑台共用同一套段推导 | 编辑台与舞台命中同一位置 |

## 8. 已知限制（不是 bug，别当 bug 修）

- 热区是**竖向条带**，动作幅度大（抬手盖胸、前倾）时和网格有偏差 —— 这是“段”的设计取舍。
- 小身体/缩放后热区看着“框到空气”：段本身是矩形，缩小后必然盖到透明处，靠 alpha 门控兜住。
- 长裙态腿热区停用是**有意的**（裙子挡住腿，现实里摸不到）。
- 抚胸时胸热区停用是**有意的**（手盖着胸口）。
- 尾巴热区是凸包 + 洞，不是逐像素；摸到尾巴与身体的交界按 z 判给身体。

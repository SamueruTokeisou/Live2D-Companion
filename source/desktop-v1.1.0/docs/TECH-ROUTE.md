## 0. 一句话总览

一个 **Electron 壳 + 本地 HTTP 服务 + 浏览器同源页面** 的桌宠系统：

- **舞台**（Electron 透明无边框窗口）只负责「角色 + 互动」；
- **设置**是普通 Electron 子窗口，**编辑台**改走浏览器 webUI（融合了原动作编辑器与验证台）；
- 角色的一切动作、表情、口播、物理，都建立在同一个核心约束上：
  **Live2D 参数的「物理前 / 物理后」两个写点**。

```
┌──────────────────────────── 主进程 app/main.mjs ────────────────────────────┐
│  窗口 / 托盘 / 全局快捷键 / 开机自启 / 安全模式 / IPC / 窗口搬运与缩放         │
│  └── 内置静态服务 src/server/stage-server.mjs（127.0.0.1:随机端口）           │
│        ├── /app/       舞台页面（Electron 窗口加载）                         │
│        ├── /app/settings.html  设置窗口（Electron 子窗口）                   │
│        ├── /app/editor.html    编辑台（浏览器打开，融合版）                   │
│        └── /api/*      ActionBus / 能力清单 / 动作文件 / 舞台 RPC            │
└───────────────┬─────────────────────────────────────────────────────────────┘
                │ 同一份 HTTP 服务
     ┌──────────┴───────────┐        ┌───────────────────────────┐
     │ 舞台渲染层            │        │ 编辑台（浏览器）           │
     │ app/renderer.js       │        │ app/editor.js             │
     │ PixiJS 8 + Cubism 5   │        │ 自己渲染一份模型           │
     │ 视线/物理/热区/气泡   │        │ 装载/试播/编辑/诊断        │
     └──────────┬───────────┘        └──────────┬────────────────┘
                │ IPC（preload.cjs）            │ HTTP（token）
                └──────────────┬────────────────┘
                               │
                    ┌──────────┴──────────┐
                    │ DSH 桥接插件         │
                    │ dsh-live2d-bridge    │
                    └─────────────────────┘
```

## 1. 运行形态与职责边界

| 角色 | 载体 | 入口 | 职责 | 不做什么 |
|---|---|---|---|---|
| 主进程 | Electron | `app/main.mjs` | 窗口、托盘、快捷键、自启、安全模式、IPC、窗口尺寸/位置 | 不碰模型参数 |
| 舞台 | Electron 透明窗口 | `/app/` → `renderer.js` | 模型渲染、互动、动作播放、气泡、物理 | 不持有设置面板 |
| 设置 | Electron 普通子窗口 | `/app/settings.html` | 设置项、表情/姿势按钮、主题、导出补丁 | 不直接改模型（走 RPC / 广播） |
| 编辑台 | 浏览器页面 | `/app/editor.html` | 动作库、关键帧编辑、试播、热区命中、诊断 | 不写舞台状态（通过 HTTP RPC） |
| 桥接插件 | DSH 插件 | `dsh-live2d-bridge` | 把会话状态/意图投到舞台；注册 `live2d*` 工具 | 不直接渲染 |

**窗口形态**

- 舞台：`transparent + frame:false + skipTaskbar + alwaysOnTop('screen-saver') + resizable:false`。
- 设置：普通窗口，保留任务栏条目。
- 编辑台：不开 Electron 子窗口，`shell.openExternal(<本地服务>/app/editor.html?token=…)`，
  自己渲染模型、自己读动作库，不占任务栏、不和舞台抢 GPU。

## 2. 核心原理：参数写点模型

这是整个项目最容易踩坑、也最值得先理解的一层。

Live2D（Cubism 5）每帧的顺序是：

```
beforePhysics  →  physics.evaluate()  →  beforeModelUpdate(coreModel.update)
```

本模型的 `physics3.json` 有 **131 条链、50 个输入、292 个输出**。其中：

- `ParamAngleX/Y/Z`、`ParamBodyAngleX/Y/Z`、`LeanInput`、`Movement*`、`Clothes*`
  这些**既入又出**：物理拿它们算头发/耳朵/衣服，又会回头重算它们自己；
- `LEGAngleZ2`、`Param33`、`LFlip/RFlip`、耳朵、头发、`LipPhysics*` 等是**纯输出**：
  物理之后写才有用，写在物理前会被覆盖。

### 2.1 三个写点

| 写点 | 时相 | 写什么 | 谁在用 |
|---|---|---|---|
| `layers.applyPhysics()` | 物理前 | 物理输入（表情、姿势、换装、lean） | `layers.js` / `poses.js` |
| `bus.flush()` | 物理前 + 物理后各一次 | 头部/身体角度（增量合成） | `pose-bus.js` |
| `layers.apply()` / `life.apply()` / `mouth.apply()` | 物理后 | 表情层、物理输出叠加、嘴型 | `layers.js` / `life.js` / `mouth.js` |
| `holds`（动作里的物理输出） | 物理后 | 腿/脚角度等绝对写入 | `idle-motions.js` / 编辑台 |

### 2.2 姿态总线（pose-bus）

`ParamAngle*` / `ParamBodyAngle*` **只允许一个写入者**。视线、姿态链、抚摸、捏脸、
待机动作都只往总线**累加增量**，由总线在物理前后各 flush 一次。

> 为什么不能各写各的：物理后会重算这些参数，最后写的人赢；
> 若视线写旧值，会把同帧的抚摸/姿态链整块抹掉；若都不写，转头又被物理削掉。
> 总线的存在就是「合成一份姿态，物理前后各喂一次」。

### 2.3 `holds`：物理输出参数

动作（`idle-motions` 的 routine）可以带 `holds`，每帧在物理之后写绝对值。
「扭扭腿」「跺脚」之所以能生效，就是腿的 `LEGAngleZ2` / `Param33` 走 `holds`，
而不是关键帧直写（直写会被物理回算吃掉）。编辑台的动作格式也支持 `holds`。

### 2.4 参数分级

- 一级（能动造型、约 20 个）：头/身/眼/嘴/眉/手臂链/lean/clothes；
- 二级（只驱动物理、几乎不改造型）：`AngleX/Y/Z`、`PositionX/Y/Z`、`ParamBreath`、`LControl/RControl`；
- 输出级（只能物理后写）：耳朵、头发、腿、`LipPhysics*`、`Tongue*`、`Jewelry*`。

完整清单与联动关系见 [PARAMS.md](./PARAMS.md)。

## 3. 交互链路

### 3.1 热区数据

- 坐标系：**模型画布像素**（3749×7697），与 PSD 同尺寸；
- 每条：`{ name, z, points[], holes[], reaction, disabled }`；
- 命中：`z` 大的优先，同 z 后加入优先；`holes` 不算命中；`disabled` 跳过；
- 播种：按蒙皮顶点/部件名分组自动铺（头/胸/腰/裙/腿/脚/尾巴），
  脸再切成 `额头 / 左脸 / 右脸`，手有动态区，长裙有独立 `长裙` 区；
- 存储：渲染层 `localStorage`（按模型名分键），补丁 `stage-patch.json` 可覆盖。

### 3.2 手势识别（`regions/input.js`）

阈值按**画布宽度比例**给，与窗口缩放无关：

| 手势 | 判定 |
|---|---|
| `tap` | 位移 ≤ 2% 画布宽 且 ≤ 420ms |
| `pet` | 按住滑动，每 3% 宽上报一次；连抚 3 次以上优先判抚摸 |
| `dragStart` | 超过阈值且持续移动 |
| 起手 | 允许起手于热区外（真实使用手不会精准落点） |

### 3.3 反应规则（`reactions.js`）

- **切换，不叠加**：同一热区同一时刻只有一组反应；
- 两边都有的表情原地保留（避免动画重播）；
- 换装 / 脱鞋 / 尾巴这类是**长期状态**，放独立 `source: 'switch'`，别的互动不许动它；
- 反应只决定「谁上谁下」，真正的写入仍在 `layers.js`。

### 3.4 特殊互动

| 互动 | 实现 |
|---|---|
| 摸头 / 点额头 | 三态循环：常态 → 爱心眼 → 黑框眼镜 |
| 捏脸 | 按左右脸分区拖动 → `CheeckPuff*` 鼓脸 + 前倾（`LeanInput`），用户手动开前倾时让位 |
| 摸胸 | 切「举手/抚胸」手型 + 分区表情，3.6s 后收手 |
| 摸胯 | 黑脸 + 脸红 + 举手护住 + 气泡台词 |
| 摸脚 / 腰 | `tickle.js`：快抖 + 小臂反相 + 耳朵扑棱 |
| 点长裙 | 撤回「裙子切换」表情，重铺腿热区 |
| 拖窗口 | 右键按住角色 / 中键任意处搬运；带物理（拖动时模型跟着甩）。左键不搬窗，只做互动 |

## 4. 动作系统

### 4.1 数据格式（`ROUTINES`）

```js
名字: {
  ms: 5200,                    // 原始时长（会被 playback 缩放）
  lines: ['…'],                // 台词（随机一句）
  face: '笑',                  // 可选：顺带触发 idle-faces 预设
  pose: '狗尾草',              // 可选：先切姿势族
  gust: 2.2,                   // 可选：一阵风（头发/耳朵）
  mouth: { open, funnel, … },  // 可选：口型
  tracks: { ParamX: [[0,0],[0.3,9],[1,0]] },  // 归一化关键帧（角度增量）
  holds:  { LEGAngleZ2: … },   // 物理输出（物理后写绝对值）
}
```

`semantics.js` 把 12 种情绪（傲娇/害羞/生气/…）固化成配方，转成同样的 keyframes：
`[[0,0],[0.18,v],[0.72,v×0.92],[1,0]]`，所以 `【情绪|傲娇】` 与 `【动作|傲娇】` 等价。

### 4.2 播放模型（`idle-motions.js`）

- **频率与速度分离**：`idleSpeed` 只决定「多久换一段」（基础 8–18 秒）；
  `actionSpeed`（0.4–1，上限 = 预设速度）只缩放轨道播放；
- **包络**：首尾各 fade，整体乘钟形包络，不会硬切；
- **让位**：用户一互动就 `pause/reset`；`manual` 动作不受让位限制（保证 agent 动作能播）；
- **链式**：`甲>乙` 依次播放；`COMBOS` 是命名组合（傲娇三拍、雌小鬼挑衅…）；
- **姿势族**：动作可先切「默认手/竖手指/举手/狗尾草」，再在族内摆；
- **让位头部**：动作含 `ParamAngle*` / `ParamBodyAngle*` 时，`headBusy()` 为真，
  视线与姿态链强度归零，结束后恢复（见 §5）。

### 4.3 时间模型

```
T = max(T1 说话时长, T2 动作时长, 900ms)
气泡显示 T；T 到点后 settleAfter(T) 撤掉本轮表情/口型/姿势
```

- `T1` 由语速表估算（见 §5.4）；`T2` 由 `idle.plannedMs(name)` 给出（含 playback 缩放）；
- `busOwnUntil = now + T + 400`：这段时间里后台状态推送不许抢气泡；
- 纯 `【表情|…】` 也有独立 TTL（默认 6000ms），不会一直挂着。

### 4.4 动作库与编辑台

- 内置动作在编辑台里可以「装载成关键帧」（`action-presets.js` 采样），
  带 `holds` 与 `base`（姿势族基底），所以能原样复现；
- 官方 `motion3` 由引擎直接播（`stage.motion`），播放期间关键帧写入让位；
- 用户动作存 `userData/actions.json`，编辑台通过 HTTP 读写，舞台重启后加载。

## 5. 表现层：让角色「活」

| 模块 | 作用 | 写点 | 关键参数/事实 |
|---|---|---|---|
| `gaze.js` | 眼珠/头/身跟随鼠标 | 总线（角度）、直写（眼珠） | head 0.9×30°，headGain 1.25，deadZone 0.06 |
| `posture.js` | 胸→腰弹簧跟随 + 呼吸 | 总线 | chest 26°，hip 11°，过冲比 0.72/0.9 |
| `pet-sway.js` | 抚摸时头按鼠标位移 50% 摆 | 总线 | 松手回落 |
| `tickle.js` | 摸腰/脚时快抖 | 总线 + holds | 小臂是物理输出，必须 hold |
| `life.js` | 耳朵/头发/耳环的惯性、扑棱、阵风 | 物理后叠加 | 弹簧 90/14，earFlip 0.35，gust |
| `mouth.js` | 呼吸微动 + 音节口型 + 情绪嘴形 | 物理后加性 | `jawGain 0.5`，LipPhysics 自带弹性 |
| `mouth/visemes.js` | 文本 → 口型时间轴 | — | 中文 200ms/音节；日 150ms/拍；英 辅 85/元 110 |
| `idle-faces.js` | 随机「笑/吐舌/单眼笑」 | 物理后 | 嘴加性、闭眼覆盖 |
| `capture.js` | 把姿态翻译成面捕通道喂物理 | 物理前 | Angle/Position/Breath/LControl… |
| `face-pinch.js` | 捏脸鼓腮 + 前倾耦合 | 物理后 + 物理前 lean | `CheeckPuff*` |
| `phrases.js` | 预设台词库 | — | 状态档 + 互动档 |

### 5.1 语速表（`visemes.js`）

| 语言 | 基准 | 细节 |
|---|---|---|
| 中文 | 200ms/音节 | 起音 62ms；三声 ×1.18、四声 ×0.94 |
| 日文 | 150ms/拍 | 长音/促音/拗音单独计时 |
| 英文 | 辅音 85 / 元音 110ms | 字母级近似 |

`SPEECH_RATES = { slow: 1.3, normal: 1, fast: 0.82 }`（时长倍数）。

### 5.2 视线让位

动作在写头部/身体角度时，`idle.headBusy()` 为真 →
`gaze` 与 `posture` 的 `strength` 归零（不是跳过 apply，呼吸和弹簧还在），
动作结束自动恢复。否则两套角度在总线上叠加，看起来是「甩头再回弹」。

## 6. 桌面集成

### 6.1 窗口尺寸与缩放

- 窗口尺寸由角色推导：`k = 540/mw × zoom`，`W = mw·k·1.12`，`H = mh·k·1.10`；
- 角色按**身体中心**摆正（静态热区包围盒中心），不受测量时机影响；
- 缩放：**按住中键 + 滚轮**（`buttons & 4`），5% 步进，0.3–3.0；
  - **以光标为中心**：记录光标下的模型点与屏幕位置，缩放 + 窗口 fit 后用 `win:bounds`
    取窗口位置，把窗口挪回去让该点仍在光标下（`settleZoomAnchor`，140ms 结算）；
  - 不用 Ctrl+滚轮：那是 Windows 桌面「缩放图标」的快捷键。

### 6.2 拖动与穿透

- 右键按住角色 / 中键任意处拖 = 搬窗口（带物理，拖动时模型甩）；左键不搬窗，只做互动；
- 指针落在不透明像素上才响应互动；落在透明区透传给下层软件；
- 动态穿透：每 700ms 重建 alpha 掩码（4px 网格），覆盖率 < 0.4% 视为没渲染出来、
  永远保持可点；`Ctrl+Alt+L` 切换穿透，`Ctrl+Alt+Q` 退出。

### 6.3 托盘 / 自启 / 安全模式

- 舞台 `skipTaskbar`，主入口是托盘：显示/隐藏、设置…、编辑台…、穿透、置顶、跟随、退出；
- 右键角色只剩「前倾 / 恢复」开关；
- 开机自启写 Windows 登录项（开发版也注册，参数传 `app/main.mjs`）；
- `boot.json`：启动 2.5s 内没完成 → 下次进安全模式（禁用硬件加速）。
  目前是「一次失败就降级」，见 §11。

### 6.4 主题

`app/theme.css` + `app/theme.js`：令牌化颜色，`auto | light | dark` 三态，
存 `settings.theme`，设置窗口与编辑台共用，跨窗口靠 `settings` 广播同步。

## 7. 编辑台（浏览器 webUI）

### 7.1 能力

| 区域 | 内容 |
|---|---|
| 动作库 | 内置待机（装载成关键帧）、姿势、官方 motion3、表情、热区 |
| 我的动作 | 关键帧编辑、参数、速度、配字、导入/导出 |
| 预览 | 中键拖动平移、滚轮缩放、双击复位、Alt+左键转头、左键点热区测命中 |
| 诊断 | 物理挂载/评估次数、播放模式、命中热区、受控参数（holds） |
| 主题 | 与设置共用三态 |

### 7.2 关键实现

- 预览是**独立的模型实例**（不是舞台的镜像），所以编辑时不会干扰桌面上的角色；
- `holds` 在物理后写；`base`（姿势族）与关键帧在物理前写；
- 当前动作含头部角度时，交互追踪暂停（诊断会标注）；
- 官方 `motion3` 用 `loop:false` + 时长兜底，避免 loop 动作让「官方动作播放中」永久挂住；
- 热区几何通过 `POST /api/stage/regions` 从舞台窗口转发（渲染层 `__stageRpc`）。

### 7.3 新增 HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/PUT | `/api/actions` | 读写 `userData/actions.json`（写需 token） |
| POST | `/api/stage/<op>` | 转发舞台 RPC（如 `regions`），需 token |

token 由主进程拼进编辑台 URL（`?token=…`），页面放进 `x-stage-token` 头。

## 8. 对外协议与 DSH 联动

### 8.1 HTTP / SSE（`stage-server.mjs`）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/version` | 协议版本 |
| GET | `/api/capabilities` | 模型能力清单（参数/动作/表情/意图词表） |
| POST | `/api/action` | 下行指令（需 token） |
| GET | `/api/events` | SSE：动作、反馈、快照（token 走查询串） |
| POST/GET | `/api/feedback` | 上行反馈 |
| POST | `/api/snapshot` | 页面心跳快照 |
| GET | `/api/state` | 快照 + 最近反馈 |
| GET | `/api/log` | 日志 |
| GET | `/api/meme/*` | 表情包图（白名单文件名） |
| GET/PUT | `/api/actions` | 编辑台动作文件 |
| POST | `/api/stage/<op>` | 舞台 RPC |

### 8.2 意图语法

`【动词|参数|…】`（全角）或 `[[…]]`（ASCII 兜底），词表封闭，越界回执：

`姿势 / 手势 / 动作 / 情绪 / 手 / 表情 / 看 / 换裙 / 尾巴 / 转身 / 说 / 停`

- `动作` 支持 `甲>乙` 链式与命名组合；
- `看` 连写多个按顺序执行（`【看|左】【看|右】` 来回转头）；
- 词表外的动词拒绝并回执，模型下一轮自己改。

### 8.3 DSH 桥接

- 舞台把 `{url, port, token, model}` 写到 `~/.dsh/live2d/endpoint.json`；
- 插件把会话状态写到 `~/.dsh/live2d/status.json`，舞台轮询投到角色；
- 插件注册 `live2d` / `live2d_status` / `live2d_actions` 三个工具；
- 回合结束把回复说进气泡（≤60 字原文，长文本压缩），`[表情: 描述]` 从表情包库取图。

## 11. 已知限制

| 限制 | 原因 | 影响 |
|---|---|---|
| 跨族手位（挡胯 / 手挡裙前）做不了 | 四条手臂美术各自独立，默认手行程 ~130px，举手族最低只到上胸 | 只能换族或二次分层（需要原始 PSD/Cubism 工程） |
| 官方 motion3 只能播、不能编辑 | 没做 motion3 → 关键帧采样 | 想要「改官方动作」只能重做 |
| 热区编辑仍缺 UI | 产品侧没有画/拖顶点 UI（编辑台只做命中测试与反应实测） | 普通用户改不了热区 |
| 安全模式一次失败就降级 | `boot.json ok:false` 直接下一次 safe | 误杀进程（2.5s 内）也会降级 |
| 多显示器 / DPI 变化未专项处理 | 窗口尺寸按 DIP 计算 | 跨屏拖动后尺寸可能跳 |
| 无 TTS / 音频口型 | `mouth.speak()` 接口留着但没接 | 口型只按文本估算 |
| 物理与动作的「让位」是粗粒度 | 按是否有头角整段让位 | 动作中途鼠标完全无反应 |

## 12. 后续规划建议

### P0（发版前后就该做）

1. **编辑台内热区可视化编辑**
   - 在预览上画多边形 / 拖顶点 / 改 z / 禁用 / 绑定反应；
   - 保存走 `/api/stage/regions`（补一个写入 RPC），直接落舞台 localStorage；
   - 收益：普通用户能自己调热区，编辑台就能覆盖全部调试需求。
2. **官方 motion3 → 关键帧采样**
   - 读 motion3 曲线，按时间采样成 `keys`，让「官方动作」也能进编辑台改；
   - 注意物理输入参数要保留 `base`/`holds` 语义。
3. **动作文件热更新**
   - 编辑台保存后通知舞台重载 `actions.json`（现在要重启）；
   - 可加一个 `POST /api/reload` 或 SSE 事件。

### P1（体验/稳定）

4. **安全模式改成连续 2 次失败才降级**，并在日志里写明原因；
5. **多显示器 DPI**：监听 `display-metrics-changed`，重新 fit；
6. **TTS / 音频口型**：`mouth.speak(0..1)` 已留接口，接音频 analyser 即可；
7. **热区反应可视化编辑器**：点热区 → 选表情/动作/台词；
8. **设置项分组与搜索**：现在设置窗口已经比较长。

### P2（扩展）

9. **跨族手位/挡胯**：需要原始 PSD 分层，属于美术管线问题；
10. **动作市场/分享**：`actions.json` 的导入导出已经有了，可以做成资源包；
11. **性能档位**：物理降频、掩码重建间隔、LOD 贴图；
12. **插件协议扩展**：情绪/组合已经可用，可加「连续动作队列」「语音」；
13. **崩溃自愈**：渲染进程挂掉自动重建窗口，不退出整个应用。

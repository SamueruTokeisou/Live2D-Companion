# Live2D Stage — 设计决议

> 本文是「已拍板」的记录，不是待选方案。改动这里要先在讨论里推翻它。

## 0. 定位

协作工作台里的**角色演出层**：只要角色、只要干净，一切编辑藏在右键面板里。
DSH 只负责拉起与转发，Stage 是独立软件。

**非目标（v1 明确不做）**：摄像头面捕、在 Live2D 里新增骨骼/变形/新模型本体、
把模型打包进发行物。

## 2. 渲染与窗口

- 窗口：Electron，`transparent + frameless + alwaysOnTop('screen-saver') + skipTaskbar`。
- **窗口尺寸由角色大小推导**（原 A/B 双自由度合并，定稿）：
  - `zoom` 表示「角色大小」：`k = 540/mw × zoom`，窗口 `W = mw × k × (1+0.12)`、`H = mh × k × (1+0.10)`。
  - 视口固定 `contain + margin 0.95`；视口 `zoom` 平时为 1，**体型变小会自动放大**（见下条），
    窗口尺寸只由画布推导。
  - 所以「角色大小」与「窗口大小」是同一个自由度：**鼠标放在头 / 胸 / 腰 / 胯 / 裙热区上，按住中键滚轮缩放**
    （每格约 1.5%、0.5% 步进；设置里不再有大小滑杆，见 §「缩放交互」）。
  - 角色摆的是**身体中心**：contain 居中的是模型画布，而角色在画布里并不居中，因此按静态热区
    （头/胸/腰/裙摆/腿/脚）求包围盒中心，换算成视口归一化偏移把它挪正。该偏移是模型常量，
    与窗口尺寸、缩放、测量时机都无关（纯几何推导，不做运行时测量），避免「切一次尺寸就偏一次」。
  - **体型变小 → 按比例放大，头部贴合气泡**：窗口尺寸由画布推导，画布不随体型变；
    而体型参数（`Clothes2`：标准 0 / Q 版 1）一拉，网格整片缩小 —— 实测头只小 16%、
    头到脚缩掉 41%，于是角色在窗口里看着变小、头离右上角气泡越来越远。
    做法：按**头到脚高度**反算放大倍数 `z = 标准体型跨度 / 当前跨度`，再把
    **头顶钉在窗口高的 9.8%**（气泡正下方）、**头心钉在宽的 51.8%**：
    `0.5 + offY/2 + (top/mh − 0.5)·0.95·z = 0.098`
    `0.5 + offX/2 + (cx/mw − 0.5)·0.95·(1+padY)·z/(1+0.12) = 0.518`
    基准（标准体型跨度）在 `Clothes2=0` 时量一次存 localStorage（换模型各存各的），
    读不到按画布高 84.6% 兜底；另有「脚底不超窗口 98.5%」的限幅。
    实测五档体型（700×1280）：头顶恒 125.4px、脚底恒 1154.4px，z 从 1 到 1.70。
  - **启动即应用设置**：`main()` 里 `applySettings(settings)` 走一遍（体型 / 视线 / 待机 / 描边）。
    以前只靠主进程「窗口尺寸变了才广播」顺带带一次，无头环境或广播晚到就会
    「设置里存着 Q 版、重启却变回标准体型」。
  - **身体中心会随体型/换装变**：热区重算之后（见 §5）要重新求一次中心并重设偏移
    （`scheduleRecenter` → `applyFit(true)`，防抖 140ms）。夹板 x ±0.6 / y ±0.9 ——
    Q 版体型的中心跑到画布上部，按公式要 ~0.51 的半窗偏移才回得正中，原来统一夹 ±0.4 会被截断。
  - **帧率上限**（设置 → 性能）：`60`（默认，限帧省电，高刷屏不再满速）或 `不限制`（=0，跟随显示器）。
    落到 `PIXI ticker.maxFPS`；状态快照里带 `fps:{cap,actual}`，排查耗电/卡顿时先看这两个数。
  - **动作写头角时视线按幅度让位**（2026-11 改）：`idle.headLoad()` 取当前动作 `ParamAngle*` 轨道的峰值角度，
    分档处理 —— **≤4° 完全不让位**（挥手/指人/跺脚这类小动作照样跟鼠标），
    **4~12° 线性打折**（戴铁盆 7° → 强度 0.63），**≥12° 才完全交给动作**（别过头 26° → 0）。
    过渡是平滑的（`frameDt*9` 逼近），不会「啪」一下抬头。
    为什么改：以前只要轨道里出现 `ParamAngle*` 就归零，用户看到的是「放个表情，头就不跟鼠标了」。
    叠加问题仍然存在（动作 20° + 视线 27°），只是小幅动作两套角度加起来也在合理范围。
  - **气泡自动隐藏的竞态**：`say(key,{ms})` 排的隐藏定时器到点时会核对 `lastKey` **和**当前文本；
    任何新内容（agent 台词 / 互动台词 / 换图）都会先 `clearHide()`。
    以前旧定时器只核对 key，换句话后仍会按点收掉 —— 表现就是「气泡时不时被顶掉消失」。
- 纯播放模式：覆盖层只渲染角色与（可选）气泡；**设置是独立窗口**（托盘 → 设置…），
  **编辑台在浏览器里打开**（托盘/设置 → 动作编辑器，走本地服务 `app/editor.html`），
  覆盖层不承载任何面板，尺寸与原内容解耦，也就不存在「为面板临时加宽」这类补丁。
- 拖动区分：指针落在**模型不透明像素**上才响应互动；落在透明区 = 透传给下层软件。

### 2.1 渲染内核（已拍板：换核）

- **采用**：`pixi.js 8` + `untitled-pixi-live2d-engine`（MIT；内部是官方 Cubism 5 框架的封装，
  原生支持 moc3 v5、逐网格乘法色/滤色、大贴图 LOD）。
- **弃用原因**（实测，不是猜测）：原方案 `pixi-live2d-display@0.4` 走 Cubism 4 管线，不认逐网格乘法色。
  本模型的鼻子阴影正是用乘法色做的 → 被画成一整块实心（旧内核里是黑块，换内核后变白块），
  瞳孔同时丢色变灰白圈。已排除贴图缺失、UV 退化、贴图索引越界、遮罩错误四种可能。
  换核后自动正常，**不需要**再隐藏 `Part10/Part46`（鼻子）之类的补丁。
- **边界**：内核只经 `src/stage/engine.js` 访问；上层只拿原语（参数/部件/动作/表情/命中/时钟）。
  若日后要换回官方 Cubism 5 SDK 直写渲染循环，只重写这一个文件。
- **实测更新顺序**（决定自定义层挂哪里）：
  `updateMotions` → `coreModel.saveParameters()` → 内核表情 → 眼眨 → 视线 `focus` → 自然运动 →
  唇形 → 物理 → pose → **`beforeModelUpdate`** → `coreModel.update()`（算顶点） → `coreModel.loadParameters()`。
  所以自定义分层（L2 表情叠加 / L5 受控参数 / 部件覆盖）一律挂在 `beforeModelUpdate`，
  而**读参数校验必须在同一帧的该时刻读**，更新后读只会拿到被 `loadParameters()` 还原的基线值。
- **物理输入有单独的写点**（踩过的坑）：`LeanInput` / `Clothes1/2` / `Movement*` 是 physics3.json 的
  **输入**，物理在 `beforeModelUpdate` **之前**就算了完 —— 写在 beforeModelUpdate 只会带动直接绑参数的网格，
  物理链条不响应，表现就是「歪得不完整」（「前倾」表情最初就是这样错的）。
  为此 `engine.onBeforePhysics()` 包了一层 `physics.evaluate`，物理输入在它之前写。
- **既入又出**的参数（`ParamAngle*` / `ParamBodyAngle*`，实测六个全是 in+out）走**姿态总线**
  （`src/stage/pose-bus.js`）：视线、姿态链、抚摸晃动、捏脸都只往总线**累加增量**，
  由总线在物理前写一次（喂给物理）、物理后再写一次（决定画面）。
  这样既不会被物理回算削掉，也不存在「谁盖掉谁」——两难是分层写同一批参数造成的，
  单层各自恢复自己的旧值只会把别的层的贡献抹掉（「脸转了头不摇 / 头摇了脸不转」就是这么来的）。
- **引擎在渲染时才推进模型**：`model.update(dt)` 只累加，真正的 `internalModel.update()` 发生在渲染管线里。
  因此确定性步进 = 「推进 delta → 渲染一次」，见 `stage.step()`。

## 3. 冲突仲裁（分层，后写覆盖先写）

| 层 | 来源 | 写哪些参数 | 可被谁打断 |
|---|---|---|---|
| L0 | 基线 / Idle 循环 | 未被上层写过的全部参数 | 全部 |
| L1 | 视线跟随、呼吸 | `ParamAngleX/Y/Z`、`ParamEye*` 的朝向分量 | L2+ |
| L2 | 表情 | 表情文件声明的参数（`Add`/`Multiply`/`Overwrite`） | L3+ |
| L3 | 动作 | 该动作曲线覆盖的参数，`NORMAL` 优先级 | L4、L5(FORCE) |
| L4 | 区域互动反馈 | 一次性，接管 150–300ms | L5 |
| L5 | Agent / 脚本 | 声明式，带 `priority` 与 `ttlMs` | 只被更高优先级 |

**硬规则**

1. 同参数由最后写入者胜出，写入按层序执行（L0→L5），不并行抢。
2. 视线是**叠加**（additive），只在动作未声明该参数时生效。
3. **退出必须显式复位**：Cubism 不会自动回默认值，动作结束后走 0.2s 缓动回到 L0 快照。
4. `FORCE` 指令可打断 L3/L4；被打断者回执 `phase:"interrupted"`。
5. 区域互动的「抚摸」是持续手势，`pointerup` 后 300ms 内不重复触发同一反应。
6. 区域互动是**动作组**：同组内按声明顺序叠加（后加覆盖同参数），不同组进来先整组撤掉再上 ——
   **切换，不叠加**（同一热区两个手势连点不会两个表情同时挂着）。开关型反馈（换装 / 脱鞋 / 尾巴）
   再点同组 = 收回；非开关组 6s 后自动收回。
   **切组时两边都有的表情要原地保留**（不删不重建）：腿部的「点击=加载」→「滑动=加载+脸红」里，
   加载必须延续，否则移除再重建会让它的动画从头播一遍（实测修复前 t0 会被重置）。
7. 换装 / 脱鞋 / 尾巴这类**切换态是长期状态**：单独一层（`source: switch`），
   别的点击、别的滑动都不许动它；只有再点同一个热区才收回。
   临时反应组（`source: reaction`）与它分两层，清组时互不牵连。
8. **摸尾巴 = 一整套反应**（2026-11-03）：起手 3.2s 窗口内，
   `被摸尾巴`（`idle-motions.js`，`manual: true` 不进随机池）＋`＞＜`＋`脸红`＋`tailPet` 台词。
   身体扭 + 甩尾（尾巴跟物理走，动的是身体），头先别开再偷偷瞟回来。
   为什么要有「窗口」：手顺着尾巴滑到腿上时会继续发 pet 事件，
   每个 pet 都会 `idle.reset()` 并换台词 —— 不做窗口就会被拆成一堆「别摸腿」。
   窗口内其它部位的 pet 事件直接忽略。
   动作本身：`tracks` 只放头/眼（别头、偷瞄、眯眼）；**扭腰甩尾由 renderer 的 `tailWag` 写入层独占** ——
   `ParamBodyAngle*` / `HipAngle*` 会被 `poseBus.flush()` 整帧覆盖（动作系统的 tracks 和 holds 都写不住，
   实测就是「身体一动不动、尾巴也不动」）。`tailWag` 是 `onBeforeUpdate` 里**排在 poseBus.flush 之后**的
   一个钩子，甩尾窗口内直接写 `HipAngleZ`（±24°）/ `ParamBodyAngleZ`（反向 ±13°）/ `HipAngleX`，
   包络是钟形，2.4 个来回、3 秒收尾。尾巴没有专属参数（模型只有一条鲸尾，跟胯/腰的网格走），
   靠甩胯带动；实测尾鳍尖端摆幅约 **270×230 模型像素**（窗口内约 40×34 px）。

## 4. 鼠标跟随（v0 已实现：三通道）

不只是眼珠。眼 → 头 → 身体，三个通道各有增益与惯性，才像「活的」。

- 通道与量程：`ParamEyeBallX/Y`（±1，最快）→ `ParamAngleX/Y/Z`（±30°，中等，含轻微歪头）
  → `ParamBodyAngleX/Y/Z`（±30°，最慢、幅度最小）。
- **幅度分配要有依据**（实测本模型，画布 3749×7697）：
  `ParamAngleY` 满偏只带动头部约 110–148px；`ParamBodyAngleY`（胸腔）满偏能带动头部约 450px ——
  埋头/抬头真正的杠杆是身体，不是头。`角度Ybs` / `身体位移RY` / `胸↓` 等是物理**输出**，写入会被覆盖。
- 因此默认值：`head 0.9`（27°）、`body 0.45`（13.5°），并做**方向非对称**：
  向下（`bowBoost 1.7`）多弯像真的低头，向上（`liftDamp 0.8`）收敛，避免整个人往后折。
- 写法是**加性**：先读当前值（含 Idle 动作自带的摆动）再加偏移并夹到 min/max，
  所以跟随不会把待机动画压死。
- 平滑：指数阻尼，三通道速度不同（眼 20/s、头 7/s、身体 3.5/s）→ 眼睛先到、身体跟上。
- 可调：`enabled / strength / deadZone`，以及每通道增益 `eye / head / headRoll / body / bodyRoll`。
  目标按视口归一化（-1..1，右/上为正）。
- **转头幅度**（`headGain`，默认 1.25，设置窗口「跟随 → 转头幅度」滑杆 0.5–2.0）：
  乘在头的通道上（歪头幅度跟随同倍放大）。因为 `ParamAngleX/Y` 量程就是 ±30°，
  增益拉的是**中段**——指针在角色附近小幅移动时的角度；满偏处会被夹在 30°，
  所以「再往上拉」不会让头扭出模型范围，只是让中段更跟手。
  实测（`headX≈0.6`）：1.0 → 14.8°、1.25 → 21.1°、1.6 → 25.1°（待机自带 ±7° 慢摆，实测取多轮交替均值）。
- **不用内核 `focus()`**：它只驱动 eyeBall 与少量角度，无法分区调增益，也会和自定义层抢参数。

## 4.5 待机动作（v0 已实现）

桌面没人互动时不至于像贴纸：常态在动，偶尔做点小事。

- **常驻微摆**：三条不同周期的正弦（重心 `ParamBodyAngleX/Z`、轻微歪头 `ParamAngleZ/Y`），
  幅度 1–2°，永远在；这是「活着」的地基，不靠随机触发。
- **随机成套动作**：每 8–18 秒挑一段（`重心换脚 / 东张西望 / 伸懒腰 / 打瞌睡 / 抖尾巴 / 理理头发 /
  吹狗尾草 / 戴铁盆`），每段是关键帧轨道，首尾归零并乘钟形包络，所以能无缝接回微摆。
- **配表情**：部分动作会顺带触发 `idle-faces` 的预设（伸懒腰 → 笑），
  伸懒腰/打瞌睡还会压一点 `ParamEyeLOpen/ROpen` 做眯眼。
- **道具类动作**：`吹狗尾草` 切 `狗尾草` 姿势 + 小 O 嘴（`MouthFunnel/Pucker/ParamMouthOpenY`）
  + `life.gust()` 放一阵风；`戴铁盆` 叠 `钢盆` 表情 + 左右摇头。
  两者经 `idle-motions` 的 `onStart/onFinish` 挂上与撤下，动作结束自动归位，不残留道具。

### 风模拟实测（2026-11）

- 模型**没有风参数**：`physics3.json` 是 131 条被动惯性链（50 输入 / 292 输出），
  VTube 配置里 `WindStrength = 0`（关着）。所谓「自带风」其实是物理链自己慢悠悠地摆。
- 舞台的「风」是 `life.gust(amp, ms)`：放大头发 Y/X 的摆动（含惯性/朝向跟随），末尾 600ms 收住；
  `吹狗尾草` 用它（amp 2.2）。
- 实测（`tmp/wind-test.mjs`，同页连测两段动作，头发参数取 10 次采样的峰谷差）：

| 动作 | 前发Y1 | 前发Y3 | 侧发X1 | 侧发Y2 | 后发X2 | 合计 |
|---|---|---|---|---|---|---|
| 吹狗尾草（gust 2.2） | 0.125 | 0.089 | 0.057 | 0.073 | 0.067 | **0.692** |
| 理理头发（无风） | — | — | — | — | — | 0.412 |

  风让头发总摆幅 +68%，肉眼是「一阵风吹过去」而不是持续乱抖；耳朵同时有扑棱 + Flip 转动。

- **配台词**：每段可选 1–3 句，按 `lineChance`（默认 0.5）随机说一句，4.2 秒后收；
  气泡正显示 DSH 状态（thinking/working/…）时**不抢话**。
- **让位**：按下 / 抚摸 / 拖拽时 `pause()`，互动结束再恢复，避免「不听使唤」的错觉。
- 写点：只往**姿态总线**累加，与视线、姿态链、抚摸晃动共存，不会互相覆盖。
- 可调：设置窗口「待机动作」开关 + 频率（0.5–2.5×，换算成 8–18 秒的间隔）。

### 4.6 窗口缩放（v0.1 起唯一缩放路径）

- 设置里「显示窗口边框」→ 舞台浮出淡蓝边框 + 八个把手（四边/四角），拖动即等比缩放。
- 比例锁定：窗口 `w/h` 固定为模型画布比；主进程按**全局屏幕光标**重算 bounds，锚定对边，
  渲染层只报告「按下了哪条边」。拖动结束把当前比例反推成 `zoom` 落盘，重启恢复。
- 上下留白 `padY`（设置滑杆 0–18%，默认 2%）：`窗口高 = 模型高 × k × (1+padY)`；
  原来固定 18%（上下各 9%）太松，收窄后窗框贴着角色，气泡留白也按窗高比例内移。
- 角色：视口 contain、zoom 恒为 1，窗口变 → 模型等比；气泡统一乘 `--bs = zoom / 0.8`，
  字号、内边距、描边、尾巴一起缩放，所以「窗口 / 角色 / 气泡」比例锁定。
- **Ctrl + 滚轮缩放已移除**：曾出现指针落在桌面时把滚轮传给桌面、把图标大小改乱。
- 边框显示期间强制整窗接收鼠标（不做透明处穿透），否则把手抓不住；关掉后恢复穿透。

### 4.7 生命感底噪（眨眼 / 呼吸 / 收工）

- **自动眨眼**（`life.js`）：间隔 2.4–5.6 秒，18% 概率连眨两下；乘在「表情之后的 eye 开合」上
  （`ParamEyeLOpen *= k`），所以 `＞＜` 这种闭眼表情不会被眨开，眯眼动作也能叠加。
- **呼吸**（`capture.js`，物理前）：`ParamBreath` 在 0.1–0.9 之间慢摆（0.19Hz）。
  实测把呼吸钉在两端时 `ChestY1` 从 -0.28 → +0.06、`ParamBodyAngleY` -4.0 → -3.2，
  胸口/前发/裙摆整片上身都有起伏；读参数要在 `beforeModelUpdate` 读（帧尾 `loadParameters()` 会还原基线）。
- **收工三连**（`agent-link.js` 的 success）：竖手指 + `兔牙` + `黑框眼镜` + 抿嘴（嘴不张就看不出兔牙），
  4.6 秒后随气泡一起收起。

## 5. 区域系统（PSD 来源）

- 区域 = **模型画布像素**坐标系下的多边形（本模型 3749×7697，与 PSD 1:1，可直接对图层）；
  导出档案时可归一化。
- **窗口尺寸与热区解耦**：热区存的是模型坐标，窗口/模型大小只是显示变换（`viewport` 的 contain + zoom + offset），
  改窗口不需要重铺、也不会错位。已验证 1280×800 / 1600×900 / 1000×1000 三种尺寸下各热区都命中并触发。
  > 注意：「角色大小」与窗口是同一个自由度（§2），所以这里说的「模型大小」不含窗口缩放；
  > 真正会改网格的是**体型参数**（`Clothes2`，含 Q 版体型）与换装 —— 见下方「身体网格重算」。
- 命中：最上层多边形优先（`z` 大者先），重叠处只触发最上层（**叠加即优先级**）。
- **透明处穿透**：几何命中后还要过 alpha 采样（渲染一帧 + `readPixels`）；落在透明像素视为未命中。
  只对**按下/点击**做这道关：悬停高亮纯几何（要「指哪亮哪」，且读像素会拖帧率）；
  采样读不到（`null`）时放行 —— 不能因为取像素失败把整块互动锁死。
  这是「只点亮着的角色」和后续窗口穿透判定的共同基础。
  > 2026-11 修：这道关此前只写在文档里，`createRegionInput` 从未收到 `isOpaque`，等于没生效；
  > 现在由 `bootRegions` 用 `stage.sampleAlpha()` 接上（模型坐标 → `viewport.modelToScreen` → 读像素）。
- **窗口级穿透（应用壳）**：窗口本身是矩形，透明区默认照样吃鼠标——停在空白处点不到后面的桌面/窗口，
  按在空白处还能把整块看不见的窗口拖走。所以应用壳自己再做一层：把当前帧渲染成 **4× 降采样的 alpha 掩码**
  （`captureMask()`：在「画完这一帧」的钩子里读像素后按格取最大 alpha），指针不在掩码上就
  `setIgnoreMouseEvents(true, { forward: true })` 让点击穿过去，挪回角色身上再收回
  （`forward` 保证忽略鼠标时仍能收到 `mousemove`，否则回不来）。
  - 掩码 700ms 重建一次；改窗口大小/缩放/拖动结束只**标脏**，下一帧正常画完顺手读回，
    不再强制重画一帧（旧实现在 resize 回调里同步 render + 整张读回，是缩放卡顿的主因，见 §11.4）。
  - 读回只覆盖「角色包围盒」（外扩两格，自适应加大；贴到内侧边界就退回整张），
    不再每次都读整张画布 —— 1128×2068 的窗口下约省 45% 像素。
  - 查表带 1 格膨胀，边沿不闪。
  - 覆盖率 < 0.4% 视为「没渲染出来」，此时**永远保持可点**——宁可吃鼠标，不做点不动的死窗。
  - 工具条、「恢复鼠标」浮标等 HTML 控件按 `elementFromPoint` 优先算「要接收」；设置界面已搬出覆盖层，
    不再参与穿透判定。
  - 因此拖动窗口只在**角色身上**起手（右键不再放设置/退出，只剩「前倾 / 恢复」开关）。
- 手势阈值按**画布宽度比例**给（窗口缩放、模型分辨率都不影响）：
  > 比例的分母取 `viewport.modelSize().mw`。这里踩过一次坑：字段名是 `mw/mh`，
  > 按 `width` 解构会拿到 `undefined` → 兜底成 1 → 阈值全变成 0.02 像素，点一下就被判成拖动/抚摸。
  - `tap`：位移 ≤ 2% 且 ≤ 420ms
  - `pet`：按住滑动，每 3% 宽上报一次；连抚 3 次以上优先判为抚摸（人在顺毛，不是要拖走角色）。
    **起手点允许在热区外**：实际使用里手不会精准落在热区里起手，要求「必须起手于热区」会把触发率压得很低。
    滑进热区才采纳，采纳时只认不透明像素；已采纳后只允许**更高 z** 的热区接管（尾巴 z=1 是兜底，
    扫过尾巴边缘再摸到腰/腿算腰/腿的），换目标时抚摸步数从头记。
    起手范围 = **应用窗口边界**（成品窗口贴住角色，窗口外的事件根本进不来），不额外做「离角色 N 像素」。
  - `drag`：位移 > 8% 宽；与窗口拖动区分，语义由上层决定（demo 里：区域拖动 vs 背景拖动）
- **两条搬窗口的路径现在共用同一套拖拽物理**：
  - 右键按住角色（身上任意点）= `dragWindow({ button: 2 })`；
  - 中键按任意处 = `bindMiddleDrag`。
  两者都喂 `state.dragVec`（pointermove 实时速度）给 `updateMotion` 的弹簧-阻尼，
  驱动 `ParamBodyAngleRX/RY`，模型自带的头发/衣服/耳朵物理整条被甩起来，松手还有约 0.5s 余震。
  **2026-11-03 起左键不再搬窗口**：以前左键按下即拖、只排除「按在热区上的那一刻」，
  按到身上没被热区盖住的一小块就整块窗口跟着走，观感是「左键变成拖拽、互动没了」。
  现在左键只做互动（tap/pet/捏脸/拖手势），右键**点一下**仍是弹工具栏（拖动过则不弹，
  用 `rightDragAt` 500ms 窗口区分）；中键不必挑位置，任意处都能搬。
- 自动铺初稿 = 七段竖切片 + 尾巴凸包：**头 / 胸 / 腰 / 裙摆 / 腿 / 脚 / 胯**（z 7/6/5/4/3/3/6）+ 尾巴（z 1）。
  横向分界全部由模型自身锚点算，不写死像素：脖子下缘、胸衣下缘、前裙上缘 +45% 裙高、前裙下缘、鞋口（腿高 10.5%）。
  只认**前裙**（`短裙`/`短裙后`）算腰裙分界 —— 长裙/身后蝴蝶结的网格会往上拉到胸口，用过一次就把腰段压成 300px 细带。
  **胯**也从锚点推导（胸下缘→腰下缘之间、腰宽收窄 35%），不再用画布比例 41.5%–50.5%。
- **身体网格重算（2026-11 起）**：热区是按网格铺的，换裙（短裙↔长裙）、拉体型（`Clothes2`，含 Q 版）
  都会换掉身体网格，固定多边形会停在旧位置（「长裙还能摸腿」「切 Q 版哪都点不到」）。
  现在按 `Clothes1..5`（裙/体型/胸衣/鞋/尾巴）的**材质签名**判断要不要重铺：每秒看一次签名，
  变了才调 `refreshBodyZones()`；`applyBodyShape` 另外防抖 500ms 触发一次。
   重铺后还有一道**校验**：体型的表达式是淡入的、姿势插值也要几百毫秒，铺早了会停在
   中间态（实测跨度差 9%，放大倍数跟着错）。所以铺完 700ms 再量一次跨度，
   差 >1.2% 才重铺（差得少 = 待机摆动，忽略），最多重试 3 次。
  不跟姿势走 —— 实测待机时同一份热区两次采样能漂 89px，跟着重铺会让热区随呼吸抖、还每两秒写存档。
  重铺只改几何、保留 `id`/`reaction`/用户其它热区，没变化不写存档。
  为控成本，`seedRegions` 先按部件名筛组**再**读顶点（715 个 drawable 里只碰 ~40 个），实测单次 2–8ms。

- **长裙态换一套热区**（2026-11）：长裙一穿，腿就被裙子挡住，现实里不该还能摸腿。
  - 判据：**看图层** `hasExpression('裙子切换')`，不能读 `param.get('Clothes1')` ——
    表达式参数是在 `coreModel.update` 之前逐帧写进去的，帧间读出来永远是被模型基线重置的 1
    （这条坑同样适用于「按参数签名判断要不要重铺」，所以签名里也把层名一起算了）。
  - 长裙：`腿` 热区置 `disabled`，按长裙网格（`长裙/长裙后/长裙蝴蝶结`）铺出 `长裙` 热区（z 4）。
    短裙：反过来（腿恢复、长裙停用）。只动这两块，其它热区（含手/脸/尾巴）不碰。
  - 交互：**点** = 撤掉 `裙子切换` 换回短裙（台词走 `longSkirtTap`）；**滑** = `skirtSway()`
    胸腔侧倾 + 骨盆反向 + 一点转动（`ParamBodyAngleZ / HipAngleZ / ParamBodyAngleY`；
    实测 `ParamBodyAngleX` 只是把胸往前推，不是转身），并说 `longSkirt` 那套亲密台词。
  - 换裙后立刻 `scheduleZoneRefresh(200)`，不等每秒一次的签名心跳。
- **热区名是画面左右，用户说的左右是角色左右**（镜像，容易踩）：
  - 画面右（热区名 `右手`）= **角色左手** = 食指手（`Movement3` 那套图）；
  - 画面左（热区名 `左手`）= **角色右手** = 抚胸手（`Movement2` 那套图）。
  - 点哪只手切哪只手，两只互不影响。
- **抬手后热区要跟着手走**（`stretchHandZones`）：抬手是换图，手部网格换到另一批 drawable，
  读取器跟不到，于是「点不到举着的那只手、只能点另一只放下」—— 这不反人类才怪。
  现在按状态把热区铺过去：竖食指 → 向上延到头部下沿并左右放宽、`z=9`（压过脸但抢不到捏脸：
  脸在头部中间，热区在头侧）；抚胸 → 朝身体中线铺到胸口（此时胸热区已停用）。
  另外两条踩过的坑：
  - 读取器按「所有手部顶点的中线」切两簇，只剩一只手可见时会把同一只手切成两块、
    凭空多出一只「右手」→ 距离过近就合并成一只；
  - 手部按**屏幕左右**重新指派（不信读取器的名字），否则抬手后左右标签会调换；
  - 手是细长条、边缘透明像素多，手部热区**跳过 alpha 门控**（`input.js`），否则点半天点不到。
- **抚胸盖住胸口 → 胸热区停用**（`syncChestZone`）：手在胸口时本来就摸不到胸，
  和「摸胸」预设语义一致；手放下自动恢复。心跳每秒跟一次，不依赖点击路径。
- **眼型互斥**（`layers.js` 的 `EXPR_GROUPS`）：`圈圈眼 / 爱心眼 / ＞＜ / 屑屑眼` 同属 `eyes` 组，
  新表情进来先把同组旧层挤掉 —— 否则「先摸胸（屑屑眼）再摸头（＞＜）」会同时挂两层，
  模型上就是两张脸叠一起。
- **居中只在体型 / 裙装真的变了才重算**：热区每次重铺都会因为待机摆动差几像素，
  以前无条件下 `scheduleRecenter`，表现为窗口跟着呼吸抽动 / 角色自己位移。
  现在用 `fitKey = 体型|裙装` 做闸门，表情切换只重铺几何、不动视口。
- **后台动作不抢显式台词**：回合结束的「会话反馈」带 `priority: BACKGROUND`，
  舞台在 `busOwnUntil`（显式 `say/intent/gesture` 后 6 秒）内直接丢弃它，
  否则刚说的话会被预设回复顶掉、还会被 success 状态的举食指盖住。
  两套参数本来就分属左右臂链（`Param36/39/40/41/42` vs `Param59..62`），可以同时挂着
  （`竖手指 + 抚胸`）。以前点哪只手都切整只「竖手指」预设，等于互相打架。
- 尾巴保持原凸包，但把与其它热区的**交集挖成洞**（`holes`）：命中与 even-odd 填充都排除洞，
  两者在形状上就不重叠（`z` 也最低，双保险）。热区换形状后重新「自动铺热区」会把洞重算。
- **尾巴隐藏态必须有恢复入口**：`尾巴开关`（`Clothes5`）一开，尾巴像素全透明 → 窗口级 alpha 掩码判定
  「不在角色身上」→ 指针直接穿透，尾巴热区永远收不到事件。所以隐藏时浮出一个**圆形气泡**
  （`#tail-restore`）：白底、`#4d6bfe` 蓝边，里面是 DeepSeek 蓝鲸 logo（`assets/deepseek-logo.webp`），
  直径按**胸宽的一半**算（≈一侧乳房大小，700px 宽窗口实测 100px），贴在大腿中部**外侧**：
  纵向 = 胯底→脚踝顶的 55%（不能取「腿」热区中点 —— 长裙态腿只剩小腿，气泡会掉到脚踝），
  横向 = 腿外缘再往外一个半径 + 一点缝，不遮大腿。点一下移除 `尾巴开关`、尾巴长回来、气泡消失。
  HTML 控件按 `elementFromPoint` 优先接收，不依赖透明像素。
- 反馈：动作 / 表情 / 参数补间 / 音效 / 气泡，逐手势可配；当前 demo 配了表情与动作。
- PSD 用途：分层拆分图 → 读出每层名称与包围盒 → 作为区域候选（含矩形一键转多边形）。
  PSD 画布与模型画布若不是 1:1，用「对齐标定」：在模型上拖两个参考点，求仿射参数。

## 5.5 骨架层（rig）与 Agent 意图

### 实测结论：这是「换图式骨架」，但举手族能连续摆

探针 `drawables`（逐 drawable 包围盒）+ 45 组参数扫描（`tmp/scan-raise3`）确认：

| 美术族 | 控制参数 | 实测可达 |
|---|---|---|
| 默认手 | `RArm/RForearm/RWrist`、`LArm/LForearm/LWrist` | 几乎不动（满行程只有约 130px），只能做细摆 |
| **举手族** | `Param62`（大臂 z）、`Param59`（大臂透视）、`Param60`（小臂 z）、`Param61`（手腕） | **整段连续**：捂嘴 / 托腮 / 侧平举 / 半平举 / 高举过头 |
| 竖指族 | `Param44`、`LWrist` | 食指位置固定，只能晃 |
| 狗尾草 | `Param36/39/41/42` | 拿草贴脸，位置固定 |

所以：
- **真正的 IK 依然做不出来**（手到不了裙前、到不了腰以下），但那不是问题 —— 举手族已经把
  「脸前 / 胸侧 / 侧平举 / 头顶」这段画出来了，够演所有「傲娇式」手势。
- 连续参数只在该族内部有效；跨族目标只能换族。
- 手位锚点用**相对族基线的偏移量**（偏移量 ≠ 绝对值，混用会让「捂嘴」变成手臂垂到裙前）。

### 分层

| 层 | 内容 | 变化方式 |
|---|---|---|
| bone（姿势族） | 默认手 / 竖手指 / 举手抚胸 / 狗尾草 | 离散，决定「用哪套图」，由 `poses.js` 切换 |
| joint（族内关节） | 举手链 `Param62/59/60/61`、肩、胸腔 | 连续；手位锚点就是这层的坐标 |
| linkage（联动） | 源骨 → 派生骨（增益 + 延迟），如抬臂带肩、肩带胸腔反侧 | 每帧派生，声明式表 |
| physics（模型自带） | 头发 / 裙摆 / 尾巴 | 由 Cubism 物理收尾，不用我们管 |

### 接口

- `src/stage/rig/rig.js`：`BONES`、`POSE_FAMILIES`、`ARM_REACH`（7 个手位锚点，**偏移量**）、
  `ARM_LINKAGE`（举手时的肩补偿）、`LINKAGE`、`GESTURES`、`planGesture()`。
- 手位锚点（偏移量）：`胸前 0` / `捂嘴 62:-1 59:1` / `托腮 62:-0.5 59:1` / `护胸 62:-0.5` /
  `侧平举 62:0.5 60:-0.5` / `半平举 62:1 60:0.5` / `高举 62:1 59:-1 60:-0.5`。
- `poses.tune(map, ms)`：把偏移量叠到当前族上（加性、带过渡、可清）；姿势层每帧
  `hold(base + tune)`，所以「动作在摆」和「姿势在哪个族」互不打架。
- 意图动词 `手势`：`【手势|捂嘴】` → 选族（举手）+ 手位锚点 + 头/身微调 + 联动。
- **0.31 新增动词 `动作`**：`【动作|杂鱼晃手】`，详见 §5.6。

### 已知边界

- 换图式模型的可达姿态 = 各姿势族的并集 + 族内微调，**不是连续空间**。
- **挡胯做不到**：默认手的连续链满行程也只有 130px，举手族最低落到上胸（y≈2030），
  裙前（y≈3600）没有对应的美术。要做得二次分层（把一只手拆成独立图层放在裙前），
  仓库里没有 PSD / Cubism 工程，只有编译好的 `moc3`，所以这条先挂着。
  替代方案：`护胸` 手位 + 后仰 + 扭身，观感接近「护住」而不是「压裙」。
- 手部热区读取器按中线聚类，抬手这类换图动作会让它认错手；**不要拿手部热区当 IK 反馈**，
  要用 `drawables` 逐 drawable 读。

## 5.6 动作预设库（成套动作）

一套动作 = 姿势族 + 手臂轨道 + 头身轨道 + 表情 + 嘴型 + 台词，由 `idle-motions.js` 的播放器统一演。

### 数据形状

```js
routine = {
  ms, pose,               // 时长、用哪个姿势族（开场切、结束释放）
  tracks: { Param: [[t, v], ...] },   // 头/身等**加性**增量，走姿态总线
  holds:  { Param: [[t, v], ...] },   // 物理输出/必须写绝对值的参数（物理前写）
  arms:   { Param: [[t, v], ...] },   // 举手链**偏移量**，每帧转成 poses.tune
  exprs: ['脸红'], mouth: {...}, lines: [...], lineChance
}
```

- `tracks` 与 `arms` 都首尾归零 → 动作结束自然回到待机 / 族基线，不会留残姿。
- `arms` 是**偏移**，播放器按包络乘 `k` 后调 `poses.tune(off, 0)`；姿势族由 `pose` 决定。
- 播放器每帧把 `arms` 求值一次（**每帧求值的纯函数**，不是触发时写一次值）——
  Cubism 参数每帧被重置，写一次就等于没写。
- **联动补偿**：`rig.armLinkageFromTune(off)` 从举手链偏移推肩/胸腔补偿
  （`ShoulderY ≈ -62×1.4 + 59×0.8`、`ShoulderZ = 62`、`ParamBodyAngleZ = -62×1.2`），
  每帧加进姿态总线。抬到捂嘴时肩会跟着提，不会像手脱臼。
- **链式动作**：`act` 的名字写 `甲>乙>丙` 就依次播；当前一段结束时自动接下一段
  （`idle-motions.js` 里的 `queue`）。例：`【动作|杂鱼晃手>捂嘴偷笑】` = 先挑衅再收住。

## 5.7 口型与语速（viseme）

模型 `model3.json` 的 LipSync 组是空的，嘴没有驱动源。现在分两层：

| 层 | 来源 | 用途 |
|---|---|---|
| 随机音节（旧） | `mouth.talk(ms)` | 没有文本时兜底 |
| **文本口型（新）** | `mouth.speakText(text)` | 气泡一出现就按实际文字排时间轴 |

### 发音表与语速表

`src/stage/mouth/visemes.js`：

- **中文**：`pinyin-pro` 取带调拼音 → 韵母归一到 `a/i/u/e/o`；声母再给一个 62ms 的起手口型
  （`b/p/m` 闭口、`j/q/x` 偏 i、其余偏 e）。
- **日语**：五十音按行归到 5 元音；长音 `ー` 拖长上一拍（×1.55）、促音 `っ` 给 105ms 闭口、
  拗音小字 `ゃゅょ` 并入前一拍（×0.62）。
- **英文**：字母级近似（拼写与发音不一一对应，只求「像在说」），元音 110ms / 辅音 85ms。
- 数字按中文念法取口型；标点自带停顿（逗号 160ms、句号/感叹/问号 300ms）。

**时长由语速表决定，不再是「字数 ÷ 固定 cps」**：

| 语言 | 基准 | 说明 |
|---|---|---|
| 中文 | 音节 200ms | 声母 62ms + 韵母；三声 ×1.18、四声 ×0.94 |
| 日语 | 一拍 150ms | 另有长音/促音/拗音修正 |
| 英文 | 辅音 85ms / 元音 110ms | 词间空格 70ms |
| 数字 | 145ms | — |

`rate` 是**时长倍率**：`'slow'` = 1.3、`'normal'` = 1、`'fast'` = 0.82，也可直接给数字（>1 更慢）。
输出 `{ units:[{ch, viseme, ms, start}], totalMs, rate }`；`speechMs(text)` 直接给时长。

实测（rate=1）：`你好呀，今天天气不错！` → 2320ms；`こんにちは、元気？` → 1590ms；`hello world` → 985ms。

### 写入

`mouth.apply()` 在嘴部待机层之上**加性**写（`sampleAt` 返回的是**插值后的连续口型**，
相邻元音之间 55% 渐变，嘴不会一格一格跳）：

```
ParamMouthOpenY += open × env × 0.78
ParamMouthForm   += form × env
MouthFunnel      += round × env × 0.9
MouthPucker      += round × env × 0.45
```

`env` 是音节包络（前 16% 张开、尾段收到 0.6）。有文本口型时关掉随机音节（`talkUntil = 0`），避免两套叠加。

### 时间轴与字幕（2026-11 定稿）

一次「说话 + 动作」有三条时长，最终以**最大值**为准：

```
T1 = 这句台词念多久（语速表 → 口型时间轴，嘴按它走）
T2 = 这个动作还要播多久（当前剩余 + 连拍队列里每一拍的完整时长）
T  = max(T1, T2, 900)
```

- **字幕/气泡维持到 T**：动作比话长时，字幕陪着动作演完；只是短句时不会被动作拖长。
- 口型只跟 T1 走，T1 结束就停，不为了等 T2 硬张嘴。
- `busOwnUntil = now + T + 400`：这段时间后台反馈抢不到话。
- **播放完毕回归默认**（`settleAfter(T)`）：动作/台词都结束后，撤掉 agent 加的表情
  （`source:'bus'`）、清嘴部情绪；手位由动作的 `onFinish` 与 11s 兜底收回。
  重启了一个动作就重置计时，不会把新一轮的状态清掉。
- 表情默认寿命：`kind:"expression"` 有动作在播就跟着 T2 退；没有动作时用 6s 兜底。

### 表情期限

表情不能永久挂着（「脸红挂一天」）：

- 意图里的 `【表情|脸红】` 不写时长 → 跟着这一轮的 T 一起退；
- `【表情|脸红|2000】` 用给定值；
- `kind:"expression"` 不传 `ms` → 有动作跟动作，否则 6 秒。

## 5.8 腿部与待机让位

- **腿是物理输出，不是可摆的骨头**：`LEGAngleZ2`（双腿转向）与 `Param33`（并/分腿）
  实测 `isOut=true、isIn=false`，往总线写会被下一帧物理回算吃掉。
  所以：
  - 常规动作**只动胯**（`HipAngleZ` / `ParamBodyAngleZ`），腿由 `rig.legChain` 算出的身体补偿跟着晃；
  - 真要摆腿（跺脚、扭扭腿），走 `holds`（物理之后写绝对值）才压得住；
  - `BONES.legs` 已标注这个限制，模型没有膝盖/脚踝参数，「抬单腿」做不出来。
- **待机让位**：随机小表情（`idle-faces`）与随机成套动作（`idle-motions`）在互动/agent 动作期间必须停手，
  否则会出现「摸胯时插一张吐舌头眨单眼」这种情绪串味。
  实现：`idle-faces.pause(ms)` + 事件入口统一调用；agent 显式动作也触发。
- **手动动作不受让位窗口限制**：`idle.trigger(name, { manual:true })` 的进度照常推进。
  以前「先 say（pause 待机）→ 再触发动作」会让动作进了池子却一帧不动，看着就是没播出来。
- **带手臂的动作自动切举手族**：`arms` 轨道是相对举手族基线的偏移，若当前还是默认手
  （`Movement2=0`），整条手链参数空转 —— `onStart` 会先 `poses.set('举手')`，结束时还原。
- **连写「看」按顺序执行**：`【看|左】【看|右】` 不再同时写目标（那样只有最后一个生效），
  而是排队，每项默认停 650ms，可用第三个参数指定。
- **姿势兜底收回**：手势/姿势是「黏」的，约 11 秒没有新姿势指令就自动回默认手
  （`armPoseAutoRelease`，护胸期间用 `holdPoseGuard` 挡住计时）。

  写需 token）、`POST /api/stage/<op>`（转发舞台 RPC，如 `regions`）。token 由主进程拼进编辑台 URL。

  设置/编辑台/意图词表/文档同步删除）、右键的「设置 / 退出」。
- **迁移**：旧 `actions.json` 里 `preset:pose:护胯` 的副本在编辑台加载时清掉（`bootData` 过滤）。

### 热区的真相（2026-11 澄清）

- **不是手画**：`seedRegions` 从 Live2D 的 drawable 顶点/包围盒生成——身体段（头/胸/腰/裙摆/腿/脚）是
  按部件包围盒切的**矩形段**，胯是按腰宽推导的矩形，尾巴是凸包；脸（左脸/右脸）、额头、左右手另有生成器。
- **是静态快照，不是逐帧跟随**：只在**体型（Clothes2）/换装（长短裙、脱鞋、尾巴）/换模型**时重铺
  （500ms 防抖 + 重铺后校验一次），姿势/动作变形期间不会重算。所以动作幅度大时，热区会和网格有偏差。
- **编辑台之前显示的是舞台的快照**：舞台按它的体型铺，编辑台预览是另一具实例，体型/姿势不同就会错位。
  现在 `localizeRegions()` 用编辑台自己的网格重铺身体段（脸/手/裙等舞台特有热区保留），并先把舞台的
  `bodyShape` 同步到预览的 `Clothes2`。
- **小身体看起来怪**：段本身是矩形，缩小后必然框到空气；不是坐标算错。
- 拖拽部件（牵手）不能依赖这套静态多边形：右键按下要用**动态命中**（`stage.hitTest` → drawable → 部件名），
  热区只负责「点一下演什么」。

### 动作库联动 / 嘴型 / 时间序列（2026-11）

- **动作内联动**（`idle-motions.linkedParams`）：动作只写「主参数」，次级动作自动补，且**动作自己写了就不补**：
  - 头转 `ParamAngleX` → 身体 `ParamBodyAngleX` 跟 28%、眼珠 `ParamEyeBallX` 先看 45%；
  - 抬头/低头 → 身体 `ParamBodyAngleY` 跟 18%、眼珠 Y 跟 35%；
  - 侧头 `ParamAngleZ` → 身体 Z 跟 22%；
  - 身体歪 → 胯 `HipAngleZ` 反向找平衡、肩膀 `ShoulderY` 跟 15%。
  关掉：`idle.set({ link: false })`。
- **嘴型预设**（`src/stage/mouth/presets.js`）：动作里的 `mouth` 可以写名字（微笑/偷笑/坏笑/O嘴/惊讶/撇嘴/叹气/咬牙/鼓腮/吐舌/嘟嘴），
  也兼容旧的数值对象。带台词的动作**说话时**把开合（open/funnel/pucker/jaw）让给口型时间轴，只保留表情形状，
  避免「音节开合 + 静态 O 嘴」叠加。
- **时间序列缓存**（`src/stage/history.js`）：环形缓冲（200 条）记 `act / touch / say / expr`，
  带 `seq / at`；`summary()` 给最近几条并换算「几秒前」。
  - 待机随机动作避开最近 4 条（`recentPicks`），不再出现「同一条动作连着演」；
  - 舞台每轮 `POST /api/snapshot` 带 `history`，agent 通过 `live2d_status` 就能知道「我刚做了什么、用户刚摸了哪」；
  - 调试：`__probe.history()`、RPC `history` / `history-all`。
- **情绪状态**（`src/stage/mood.js`）：互动累积五种权重（害羞/生气/开心/好奇/困倦），半衰期约 15 秒；
  待机随机按 `ROUTINE_MOOD` 标签加权（害羞多 → 更常理头发/偷瞄，生气多 → 更常别过头/嫌弃）。
  和 history 的分工：history 记「发生过什么」，mood 记「攒成了什么心情」。调试：`__probe.mood()`。
- **编辑台数值输入**：参数值从只读数字改成可编辑 `<input class="num">`，点一下全选、回车/失焦夹回量程并同步滑条；
  改动落在当前时间的关键帧（没有就自动建）。

### 缩放交互（2026-11）

- 设置里的「角色大小」滑杆已删除：要来回拖、又看不到基准，比直接指着角色缩差太多。
- 现在：鼠标放在 **头 / 胸 / 腰 / 胯 / 裙** 热区上，**按住中键滚轮**缩放，**每格约 1.5%**（0.5% 步进），范围 0.3–3.0。
  - 一帧只结算一次（`requestAnimationFrame` 聚合 `deltaY`）：不丢格、不排队 IPC，也不会拿到过期的 `settings.zoom`。
  - **以光标为中心（2026-11 二改：矩形绕光标缩放）**：用户给的等价定义 ——
    矩形 (0,0)-(3,4)、光标 (1,1)、放大 2 倍 → 矩形变成 (-1,-1)-(5,7)。
    即：新宽高 = 旧宽高 × k，新左上角 = 光标 − (光标 − 旧左上角) × k。
    实现上渲染层只把「光标屏幕坐标 + 缩放比 k」交给 `win:fit`，主进程按自己的旧 bounds **一次 `setBounds`** 算完；
    内容跟着窗口等比放大，所以「光标下那个点不动」是这条规则的结果，不再是另一套补位逻辑。
    实测（`tools/lab/zoom-rect-probe.mjs`）：w/h/x/y 与公式完全一致（偏差 0），光标下模型点偏移 0.6px。
    旧实现是「先按中心缩放 → 140ms 后取 bounds 补一次位移」，resize 异步，补位算在旧布局上，误差逐格累积。
  - 不用 Ctrl+滚轮：那是 Windows 桌面「缩放图标」的快捷键，指针一瞬落在透明区就会把用户图标拉大拉小。
  - 中键按住才响应（`WheelEvent.buttons & 4`），没按中键完全不插手。
  实现：`bindZoomWheel()` → `regionAtClient` 命中主体热区 → `shell.set({ zoom })` → 广播 →
  `applySettings` 只在 `zoom` 变化时 `applyFit()`（窗口跟着角色走）。
- 其他位置滚轮不响应；`Ctrl` 没按下也不响应，避免和页面滚动/缩放打架。
- 探针：`__probe.zoomAt(热区名, deltaY)` 直接模拟一格滚轮，`__probe.zoom()` 读当前值。

### 拖窗口：事件驱动（2026-11 二改）

- 第一版：每次 `pointermove` 发 `win:move`，主进程 `getPosition()+setPosition()` —— 几百次 IPC/秒 + 取整回读，一卡一卡。
- 第二版：主进程 16ms 定时器读 `screen.getCursorScreenPoint()` 搬窗口。**实测这个定时器在 Windows 上退化成 ~30ms 一拍**
  （`STAGE_DRAG_LOG=1` 的日志：tick 间隔中位 30ms），快速拖动就是 33Hz 一跳一跳。
- 现在：**事件驱动搬运**（拖动期间冻结角色已于 2026-11-04 移除）。
  - `pointerdown` 把按下事件的 `screenX/screenY` 作为锚点发给主进程（不用主进程自己读光标，避免 DPI/取整差一截导致起步跳一下）；
    每个 `pointermove` 发 `win:drag-move`，主进程直接 `setPosition(起点 + 事件坐标 − 锚点)`，一事件一挪。
  - **冻结开关已删除**：它会停掉出帧循环，把拖动卡顿藏起来（测试时反而看不到真实表现），
    也让「拖拽中物理可调」这件事没法验证。现在拖动期间物理/动画照常跑，窗口由事件驱动搬动。
    想复现「只搬静态图」的老行为，直接用隐藏窗口（停帧）那条链路观察即可。
  - 性能实测（`__perf.snapshot()`）：每帧我们的 JS（pre/post 两层）合计 **0.1ms 量级**，
    帧间隔中位 21.8ms（≈46fps），停掉渲染后 rAF 也是 21.6ms —— **瓶颈在透明窗口的合成/帧调度，不在物理**。
    所以「要物理就不流畅」并不是物理的锅；拖动期间帧间隔稳定 22ms、无长停帧，
    窗口位移与事件累计 1:1（480px/480px）。
  - 定时器降级成兜底：连续 45ms 没有事件才读一次光标；同位置不重复 `setPosition`。
- 单测：`tools/lab/drag-log-probe.mjs` 统计拖动日志（位移与事件是否 1:1、有无长停帧）。
- 诊断：`STAGE_DRAG_LOG=1` 启动后拖一次，松手写 `%APPDATA%/Electron/drag-log.json`
  （每帧记 `via` = ev/poll、光标、目标、实际位置），用 `tools/lab/drag-log-probe.mjs` 统计。

### 偶发抖动 / 位移（2026-11 排查）

「中心逻辑」确实是元凶之一，但不是唯一：

| 问题 | 表现 | 修法 |
|---|---|---|
| `applySettings` 里每次广播都 `applyFit()` | 设置一变就重算居中 → 角色整体挪一下 | 只有 `zoom` 真变了才重算 |
| `headBox()/bodySpan()` 每帧读热区 | 热区周期性重铺，差几像素 → 缩放/偏移跟着抖 | 按「体型+裙装+模型」缓存，换装才失效 |
| 偏移未量化 | 亚像素级变化也会被视口吃进去 | `zoom/x/y` 量化到 0.001 |
| 中键拖动定时器泄漏 | 指针在窗外松开时收不到 `pointerup`，主进程定时器继续把窗口拽向光标 → **偶发位移** | 渲染层在 `window` 上捕获 `pointerup`；主进程 60s 超时兜底 |

静置 90 秒实测（`STAGE_DEBUG_MOVE=1`）：窗口 x/y/尺寸全程不变，只有启动时一次 `[fit]`。

> 顺带记一笔：非正常退出（2.5s 内被杀/断电）会让下次启动进入 **safe mode**（关硬件加速 → SwiftShader 软件渲染，帧率骤降）。
> 排查卡顿时先看启动日志的 `safeMode`。若频繁误判，可把「连续 2 次失败才进安全模式」作为后续优化。

### 动作速度（2026-11）

`idleSpeed` 只管「多久换一段动作」，**不再兼职播放速度**（原来两者共用一个倍数，
调高待机频率会把动作也加速到 2.5×，看起来像瞬移）。

| 设置 | 作用 | 范围 |
|---|---|---|
| 频率 `idleSpeed` | 随机动作的间隔（8–18s ÷ 倍数） | 0.5–2.5 |
| 动作速度 `actionSpeed` | 动作轨道的播放速度 | 0.5–1.0（**上限 = 预设速度**） |

- 上限锁 1.0：再快手臂就像被瞬移；`idle.set({playback})` 里也会夹回 [0.4, 1]。
- **手和裙子不跟着变速**：`poses.set()`（姿势族/贴图切换）与裙子切换都用固定时长，
  因为那是部件淡入淡出，变速会让贴图糊在一起。
- 字幕的 T2 用真实时长（`remaining()` 已除以 playback），所以慢放时字幕会跟着变长。
- 编辑器预览也有独立的速度滑杆（0.5–1.0），只影响预览时间轴。

## 10. 原生 Cubism Core（可选加速）

用官方 C API 的 `Live2DCubismCore.dll` 替换 WASM 版核心，引擎代码零改动。
实现与构建细节见 `native/cubism-core/README.md`。

| 指标 | WASM | 原生 |
|---|---|---|
| `update()` 中位 | 8.2ms | **1.7ms** |
| 整帧（pixi8 / pixi7） | 24.5ms | 15.0 / 12.7ms |
| 帧率 | ~41fps | 67–79fps |

正确性：同参数下 58967 个顶点与官方 WASM 版逐点对比，最大误差 0。

开关：`STAGE_NATIVE_CORE=1` 或 设置 → 性能 → 原生 Cubism Core（需重启）。
开关会改舞台窗口的 `sandbox` 与 `contextIsolation`（为了在页面世界拿到 `require` 加载 `.node`），
默认关闭时安全配置不变。

### 引擎差异：pixi7 的尾巴软边（2026-11-03 定位）

pixi7（cubism4mul）渲染本模型时，尾巴轮廓外会多出一圈**半透明块状软边**；
同一份贴图换 pixi8（untitled）则干净。已排除的因素：

- 贴图透明区 RGB 不是 0（texture_02 透明区 RGB≈25）→ 两条路都已 `alphaMode=PMA`，不是它；
- mipmap：pixi7 的贴图默认开 mipmap，关掉并 `dispose()+update()` 重传后伪影仍在 → 不是它；
- 模型用了大量裁剪蒙版（715 个 drawable 里 181 个带 mask、51 个 inverted），
  pixi7 的 mask 渲染路径（mask render texture + 混合）是最可疑的一环，未继续深挖。

结论：**默认走 pixi8（`engine: 'default'`）**，pixi7 保留为实验选项（设置里标注伪影）。
若后续要救 pixi7：先对比 `MaskBufferSize` / mask 渲染目标的分辨率与采样方式，再查 blend state。

验收/诊断：`__probe.textures()` 看贴图 alphaMode/mipmap；`__probe.zones()` 看热区；
尾巴边缘特写可在编辑台或窗口截图后裁剪对比。

两个 API 语义坑（都已修）：

- `csmResetDrawableDynamicFlags` 是「重置回初始状态」，**可见位仍为 1**；实现成清零会让
  715 个 drawable 全被判不可见 → 画面全透明但 rAF 依旧 100fps（很有迷惑性）。
- `csmGetVersion()` 返回 `unsigned int`，不是字符串。

剩余瓶颈：绘制（715 次 draw call）已占整帧的大头；再往下要走批次合并/换渲染后端。

## 11. 帧节奏（vsync）

单帧工作量约 11ms（Core 求值 2.7 + 绘制 5.9 + 其他），正好卡在 120Hz（8.3ms）与
60Hz（16.7ms）两个 vsync 档之间，于是帧率在 60↔120 之间来回跳，观感就是
「一会粘滞、一会又极度流畅」。

处理：舞台进程解除 vsync（`disable-gpu-vsync` + `disable-frame-rate-limit`）。

| 指标 | 开 vsync | 解除 vsync |
|---|---|---|
| 帧间隔中位 | 15ms 且忽快忽慢 | **稳定 11.4ms** |
| p99 | 28ms | 17.5ms |
| >33ms 的帧 | 3 个/8s | **0** |

`STAGE_VSYNC=1` 可退回系统默认。注意开关必须在 `app/main.mjs` 顶部、
`app.requestSingleInstanceLock()` 之前 append，晚了不生效。

### 引擎切换与重启

引擎分支（pixi7/默认）和原生核心开关都是**建窗时定死**的（URL 查询串 + sandbox/contextIsolation），
只 reload 改不动。托盘菜单「重启引擎」与设置页「立即重启引擎」会销毁舞台窗口再重建：

- 销毁窗口会触发 `window-all-closed`，必须用 `restarting` 标记豁免，否则整个应用会直接退出
- 托盘、子窗口、光标 feed 不受影响，只有舞台窗口重建
- 舞台位置在重启前写回 settings，重建后不会跳回屏幕角落

### 拖动位置合帧

慢帧时 `pointermove` 会堆一串，逐条 `win:drag-move` 就是连续多次 `setPosition`
（每次都要重新合成窗口），观感是「卡一下之后整段发粘」。现在右键/中键拖动都走
`createMoveQueue()`：只发最新位置，松手前补发最后一帧。

> 2026-11-03 修：合帧器原来挂在 `requestAnimationFrame` 上 —— 渲染掉到 30fps 时，
> 窗口位置消息被渲染帧的尾巴拖着，表现是「窗口一顿一顿」。现在**独立调度**：
> 第一个事件立即发（只叠一次 IPC），之后最多 8ms 一拍，永远只发最新坐标，不积压。

实测快速拖动：73fps 稳定（中位 13.8ms，max 16.5ms），位移仍 1:1 精确（480/480、160/160）。
测合成事件 6 步 × (10,5) 的位移：窗口实际 60×30，一像素不差。

## 11.4 性能四项（2026-11-03）

按「缩放卡顿 / 拖动粘滞 / 缩放反馈 / 持续渲染成本」四件事逐项处理，每一处都是先定位再测量。

### ① 缩放卡顿：掩码不再强制重画、只读包围盒

- 旧路径：`resize` / 拖动结束 → `refreshMask(true)` → `alphaMask()` 同步 `renderer.render()` **再** 整张
  `readPixels` → 降采样。窗口 800×1000（DPR 2）时一次读 1600×2000×4 ≈ 12.8MB，读像素要等 GPU 同步。
- 新路径：`dirtyMask()` 只置 `maskPending`，由 `afterRender` 钩子在「本来就画好的那一帧」里读；
  读回区域 = 上一帧内容包围盒（按块对齐 + 自适应外扩，贴到区域内侧边界就加大，连贴三次退回整张）。
- 实测（1128×2068 窗口）：读回 752×1696 ≈ 45% 像素；降采样循环也跟着只跑这块区域。
- 代码：`src/stage/mask-read.js`（两个内核共用），`renderer.js` 的 `dirtyMask()`。

### ② 拖动粘滞：位置消息独立调度

见上一节「拖动位置合帧」。

### ③ 缩放反馈：专用通道，松手才落盘

- 旧路径：滚轮一格 → `shell.set({zoom})` → 主进程 `applySettingsPatch()`：写 `settings.json` +
  全窗口广播 + 重建托盘菜单 → 渲染层再走 70ms 尾沿防抖 → `win:fit` 又一次落盘。
  一格滚轮就是两次磁盘写、两次广播、一次托盘重建。
- 新路径：滚轮直接算目标尺寸，走 `win:zoom`（`shell.zoom`）**只挪窗口**：内存里更新 `settings`，
  420ms 内没有新的缩放就统一落盘 + 广播一次（`scheduleSizePersist`）。渲染层当场更新视口/气泡，
  不再等广播往返。
- 实测：滚轮 → 窗口变高 ≈ 82ms（一次 rAF + IPC + resize）；连续 8 格滚轮期间 `settings.json`
  **零写入**，停手后写一次，最终 zoom 1.6 正确落盘。

### ④ 持续渲染成本：GL 状态去重 + 空闲物理降频（2026-11-03 二轮）

先量再改。安静场景（关待机/表情/气泡）下实测，窗口 677×1242、DPR 1：

| 指标 | 数值 |
|---|---|
| 每帧 `drawElements` | 678 次 |
| 可见网格（`getDrawableDynamicFlagIsVisible`） | 462 / 715 |
| 其中蒙版绘制 | ≈216 次 |
| `internalModel.update` | 5.2ms（物理 2.5 + 其余 2.7） |
| `renderer.doDrawModel` | 7.8ms |
| 帧间隔 | 13.2～15.3ms |

**试过但放弃的：网格缓冲缓存**（`mesh-cache.js`，index/uv 只传一次、vertex 走 `bufferSubData`）。
实测反而更慢（同窗口 12.9 → 13.7ms）：Cubism 本来就共用 3 个 GL 缓冲，
改成每网格一份独立缓冲会**破坏缓冲复用**，每帧多出几百次 `bindBuffer` 换绑，
再叠上内容比对的 JS 开销，净亏。默认关，`?meshcache` 可开（诊断用）。

**落地有效的两项：**

1. **GL 状态去重**（`gl-state-cache.js`）：拦截整个上下文的幂等状态设置，
   值没变就短路 —— `useProgram` / `bindBuffer` / `bindTexture` / `blendFuncSeparate` /
   `uniformMatrix4fv` / `uniform1i` / `uniform4f`。
   注意两处坑：① 纹理绑定要按「激活的纹理单元 + target」做键（TEXTURE1 是蒙版、TEXTURE0 是图集，
   只按 target 记会把两个单元混成一个）；② `location === null`（参数被着色器优化掉）必须直接透传。
   `vertexAttribPointer` / `enableVertexAttribArray` 的去重**默认关闭**（`en.attrib`，
   属性指针状态按 VAO 存、风险高）——打开能再多省一点，但可能引起画面错位。
   实测 tick 13.4 → 12.5ms（约 −7%）。

2. **空闲物理降频**（默认关，`?physhalf` 打开）：物理 2.5ms/帧，静止时隔帧跑。
   实测能再省 1ms，但**观感有「跳」的风险**（参数每两帧才更新一次），所以默认不启用；
   打开后一有指针输入或用待机动作在演就回满帧。

**合计**：同窗口安静场景 15.0 → 11.0ms（约 −27%），帧间隔 15.3 → 11.2ms。

### 回滚记录（2026-11-03 晚）

上面这两项（GL 状态去重、空闲物理降频）**已全部撤回**：实装后出现「脸部概率性抖动」，
且用户体感卡顿没有改善 —— 收益（同窗口约 2～4ms）不值得承担画面错误的排查成本。

- `src/stage/gl-state-cache.js` / `src/stage/mesh-cache.js` 已删除，两个引擎不再包装 GL 上下文；
- 物理恢复每帧计算，`setPhysicsHalf` / `?physhalf` 一并移除；
- 托盘里的「关闭渲染缓存」「锁定 60 帧」两个排查开关也删掉（glSafe 设置不再存在）。

体检结论（留着以后别再踩）：这台机器是 240Hz 屏，而应用不限帧（`fps: 0`）时渲在
56～75fps 之间，每帧占 4 或 5 个刷新周期 → 节拍不均（实测帧间隔 17.7 / 35ms 交替），
脸部这类高对比细节最容易看出来。

**已按这条结论修好（2026-11-04）**：

- 恢复系统 vsync（删掉 `disable-gpu-vsync` / `disable-frame-rate-limit`，只留 `STAGE_NO_VSYNC=1` 排查口）；
- 出帧改由引擎内的 `frameLoop` 按刷新网格锚定：`target = 锚点 + k × (整数拍) − 提前一拍`；
- **帧率固定 60，不再可调**（`settings.fps` 从默认值、设置页、托盘全部移除；子窗口打开时降 30）；
- resize 改为「记待办、下一帧统一重排」，与出帧同拍。

实测（打包版 457×837，240Hz）：60.0～60.5fps，间隔 4 拍占 239/240，p90 16.8ms。
细节与对照数据见 `docs/PERF-RESEARCH.md` §8。

保留的仍是第一轮的成果：掩码只读包围盒、拖动独立调度、缩放专用通道。

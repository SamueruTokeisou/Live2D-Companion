# 教程：从零做一个自己的 Live2D 桌宠（经验版）

这不是 API 文档，是**做这个项目踩出来的结论**。想看「自己搞一个」该怎么取舍，看这篇；
想看现成代码怎么改，看 [EXTENDING.md](EXTENDING.md) 和 [SPEC.md](SPEC.md)。

先说结论：**难点不在 Live2D，在窗口、帧调度和交互判定。** 模型加载是 SDK 的事，
剩下三样才是决定「像不像活的」的地方。

---

## 0. 选型：用什么跑

| 方案 | 优点 | 坑 |
|---|---|---|
| **Electron + Pixi + Cubism Web SDK**（本项目） | 前端生态全套、热更新快、Cubism 官方 web 运行时 | 透明窗口合成开销大；打包 400MB+ |
| Godot + Cubism SDK | 渲染效率高、鼠标穿透有原生支持 | 要自己写 C#/GDScript 绑定；生态小 |
| WPF（VPet 路线） | 原生窗口行为最好、体积小 | 动画/Live2D 支持绕；皮肤系统要自研 |
| 直接 OpenGL/C++ | 极限性能 | 开发成本高，桌面宠物这点性能用不上 |

**建议**：先确认你要的是「AI 伙伴」还是「会动的壁纸」。前者选 Electron（要接聊天/工具生态），
后者选引擎原生方案更省心。

另外一条硬规则：**模型版权先落实**。Cubism 模型（.moc3）的授权通常禁止二次分发，
发布版别内置别人的模型 —— 本项目就是「完整版内置、发布版不内置」。

## 1. 窗口：透明、置顶、穿透

```js
new BrowserWindow({
  transparent: true, frame: false, resizable: false, hasShadow: false,
  skipTaskbar: true, alwaysOnTop: true,
  backgroundColor: '#00000000',
})
win.setAlwaysOnTop(true, 'screen-saver')   // 压过大多数窗口；'normal' 不够
win.setIgnoreMouseEvents(true, { forward: true })   // 穿透
```

要点：

1. **透明 + 无边框 + 置顶**三个一起配，少一个都不一样。
2. `setIgnoreMouseEvents(true)` 之后窗口不再吃鼠标，但 Windows 上 **`forward: true` 的 mousemove
   未必能收到**（Electron 高版本实测收不到）。想「悬停变可交互」就得：
   主进程以 30Hz 轮询 `screen.getCursorScreenPoint()` → 推给渲染层 → 渲染层按角色轮廓判断。
3. **别用全屏透明窗**。全屏透明置顶窗会触发 Windows DWM 的视频合成黑屏
   （条件：透明置顶 + 非穿透 + 可聚焦 + 完整盖住视频窗）。窗口就做成「角色包围盒 + 一点余量」。
4. `alwaysOnTop` 打开时，全屏游戏/视频可能被挡；给用户一个托盘开关，别做成不可关。
5. 任务栏图标：`skipTaskbar: true` + 托盘图标 + 全局快捷键（本项目 Ctrl+Alt+L）找回穿透后的窗口。
   穿透态下用户点不到它，**必须留后路**。

## 2. 帧调度：不要相信 `maxFPS`

这是本项目花时间最多的一块，结论直接抄：

- **别用 `ticker.maxFPS`**（Pixi）或「在 rAF 里数帧跳过」。跳过哪一帧由系统决定，
  在 240Hz 屏上会退化成 `3.4 / 7.7` 拍交替 —— 比不限帧还抖。
- 正确做法：**按显示刷新周期的整数倍出帧**。
  1. 安静状态下采 41 次 `requestAnimationFrame` 间隔 → 中位数 → 吸附到标准刷新率
     （240/180/144/133/120/100/90/72/60）；
  2. `beats = ceil((1000/fps) / P)`，`step = beats * P`；
  3. 目标时刻 = `anchor + k * step`（**不要累加 step**，浮点误差几十秒后会偏一整拍）；
  4. **提前一拍开工**（`lead = P`）：单帧耗时接近槽长时，正好到点才开始会赶不上提交，
     浏览器把 BeginFrame 推后 —— 实测 60fps 档只剩 51fps、17% 掉帧。提前 4.17ms 就稳了。
- 掉拍时**跳到当前该在的拍，不追帧**：`k = max(k+1, floor((now-anchor)/step)+1)`。
- 用 `performance.now()` 时间戳对齐，不用 `Date.now()`。

实测参考（RTX 4070 Laptop + 2K@240Hz，675 drawElements 的模型）：
单帧 12.5–14ms，其中模型更新 ~5.2ms（物理 2.5ms）、`doDrawModel` ~7.8ms。
**透明窗口的合成/帧调度才是上限**：关掉渲染后 rAF 间隔不变，说明不是 JS 慢。

## 3. 模型加载：贴图尺寸是内存杀手

- Cubism Core（`live2dcubismcore.min.js`）必须先加载，再加载 moc3；官方 WASM 求值 ~8ms/帧，
  走 N-API 原生桥能到 ~1.7ms。
- **4096/8192 贴图是内存黑洞**：本项目实测贴图 592MB → 缩到 2048 后 64MB，
  整个进程 2.0GB → 0.6GB。首次启动自动缩一次（生成 `_opt2048` 副本，不改原模型）。
- `model3.json` 里 `LipSync` 组可能是**空的** —— 这时模型完全不会动嘴。
  要么自己驱动 `ParamMouthOpenY`，要么换模型（本项目就是自己驱动，见第 7 节）。

---

## 4. 物理：帧间隔不齐 = 脸在抖

Cubism 物理是**固定步长 + 累加器**（默认 60Hz）。如果你的帧间隔忽 16ms 忽 33ms，
物理每帧走的步数不均匀，头部参数就会小幅抽动 —— 看起来像「脸在抖」。

对策：
- 先把帧调度钉稳（第 2 节），物理自然就稳。
- 物理输入参数（角度等）必须在 `physics.evaluate()` **之前**写；
  物理输出参数（`Param44` 这种）只能在**之后**写，写错顺序表现为头/头发直接画没。
- 想加「甩动感」：拖拽速度写成物理输入，让它自己晃，不要手动插值。

---

## 5. 命中：热区要按「蒙皮后的顶点」铺

- 不要用矩形硬编码：模型换了/换了体型就全错。
- 做法：取模型当前帧的**已蒙皮顶点**（`coreModel.getDrawableVertexPositions()`），
  按部件分组算包围盒。脸/手/额头这些小组件天然好算。
- **致命时序坑**：模型一帧都没更新过时顶点是空的，构建器会返回 `[]`，
  迁移「不报错也不加东西」→ 热区永久丢失，而且残缺存档会被写下去。
  启动时先强制更新一帧（`stage.advance(16.7)`），并给「缺组就下一帧重试」的兜底。
- 透明区不该吃鼠标：把当前帧缩略成 alpha 掩码，指针不在角色像素上就 `setIgnoreMouseEvents(true)`。
  掩码别每帧读（GPU 回读很贵），按需 + 缓存。

---

## 6. 拖拽：事件驱动，别轮询

- 第一版「每次 pointermove 发 IPC + getPosition/setPosition」→ 几百次 IPC/秒，一卡一卡。
- 第二版「主进程 16ms 定时器读光标」→ **Windows 上定时器会退化成 ~30ms**，33Hz 一跳一跳。
- 现在：`pointerdown` 把 `screenX/screenY` 当锚点发过去，`pointermove` 只发屏幕坐标，
  主进程算 `setPosition(起点 + 事件坐标 - 锚点)`，一事件一挪；
  指针事件再密也只发最新坐标（8ms 合帧），不排队。
- **冻结角色来换流畅是伪解**：停掉渲染后拖动确实顺，但你会失去甩动/物理反馈，
  而且它把「卡」藏起来了，让你没法继续优化。本项目已经删掉这个开关。
- 失焦 / pagehide / pointercancel 都要收尾（否则定时器残留，窗口会自己往光标跑）。

## 7. 口型：三条路

1. **G2P + 音节时间轴（离线、无音频）**：中文走拼音韵母、日语假名、英文近似；
   把文本切成音节，每音节给 `{open, form, funnel, round}`，用 `env` 做包络。
   本项目走这条（`mouth/visemes.js`），好处是不依赖 TTS、不需要音频。
2. **音频能量（AnalyserNode RMS）**：实时、简单，但只有开合、没有元音差异。
3. **TTS 自带音素时间戳**：最准，接起来最麻烦。

工程要点：
- **用加性写入**（`set(cur + delta)`），不要覆盖：表情层已经写过嘴，覆盖会把「＞＜」顶掉。
- 音节之间要**插值**，不要离散查表 —— 那是「嘴一格一格抖」的来源。
- 张嘴大于 0.5 时带一点 `JawOpen`，不然像嘴被撕开。
- 停顿/换气是「像人」的关键：纯正弦开合一定假。
- 要给别人接 TTS 留口子：本项目 `registerLipSync()` 就是这个口子（见 EXTENDING.md）。

---

## 8. 待机与动作：让人「自己动」

- **姿势（pose）用绝对值，待机动作（routine）用相对增量曲线**：两者语义不同，别混。
- 动作是「关键帧 + 时长」，随机池要**排除**情绪类动作（害羞/生气只该被点名触发）。
- **情绪加权**：摸头→害羞、被戳→嫌弃，按权重影响下一次随机动作，比纯随机「活」得多。
- 视线跟随鼠标：坐标要从屏幕 → 客户区 → 画布 → 模型，注意 DPI 缩放与画布偏移；
  动作在写头部角度时，视线要让位（否则两个源抢同一参数，抖）。
- 动作要有「兜底收回」：举手这类姿势没人放下会挂一整天，加一个超时自己回默认。

## 9. 打包与分发

坑（都踩过）：

1. `--ignore` 用「路径片段」会**误伤依赖**：`node_modules/pixi.js/dist/` 被排掉 → 黑窗口。
   要按「仓库根的第一段」判断，别按片段。
2. 打包前**先关掉正在运行的实例**，否则 `EBUSY: unlink ...icudtl.dat`。
3. 压缩包别用 `tar -a`（bsdtar 写 zip 默认**仅存储**）：432MB 目录打出来 425MB，
   而 7-Zip 是 151MB。用 7-Zip 或 `Compress-Archive`。
4. 首次启动要有**引导窗口**：没模型时别「双击一下没了」。
5. 日志落盘（`%APPDATA%/.../logs/main.log`）—— 用户报「打不开」时这是唯一线索。
6. 发布版别内置模型（授权）；贴图自动压缩放默认流程。

## 10. 长跑稳定性（最容易漏）

| 问题 | 现象 | 对策 |
|---|---|---|
| 隐藏窗口不停帧 | 托盘隐藏后仍 60 帧，白占一个核 | 主进程推可见性 → `cancelAnimationFrame`（`pause()` 不够，它只是每帧早退） |
| WebGL 上下文丢失 | 合盖唤醒后角色变白板 | `webglcontextlost` → `preventDefault()` → reload 重建 |
| 渲染进程崩溃 | 角色无声消失 | `render-process-gone` → 限次自动 reload |
| 长休眠时间跳变 | 醒来瞬间连刷几十帧 | 帧号跳拍不追帧（见第 2 节） |

## 11. 一张图总结

```
主进程 main
 ├── 窗口（透明/置顶/穿透/托盘/全局快捷键）
 ├── 拖拽搬运（事件驱动，8ms 合帧）
 └── 崩溃自愈 / 可见性推送
渲染层 renderer
 ├── 帧循环（刷新周期网格 + 提前一拍 + 不追帧）
 ├── 模型（Cubism Core + 贴图压缩 + 物理定步）
 ├── 交互（蒙皮顶点热区 + alpha 掩码穿透 + 视线跟随）
 ├── 表演（姿势 / 待机动作 / 情绪 / 口型）
 └── 扩展（lipSync provider / action pack）
```

**最后一条经验**：先让「帧稳」，再谈动画；先让「命中准」，再谈互动。
顺序反了，会一直在调一个根本不该抖的东西。

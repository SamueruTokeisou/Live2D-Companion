# P3 文字对话：使用与验收

更新：2026-11-23。版本：0.4.0-dev。已接入一个真实后端并完成多轮中文、流式输出、停止和恢复的基础验收；不是整体稳定版。P1 的内存增长与休眠恢复遗留项继续保留。

## 当前接入的是什么

本轮按项目所有者“先调用你的接口”的指令，使用官方 **Codex App Server**，复用本机已经存在的 ChatGPT 登录。不是把当前维护聊天转换成服务，也没有把登录令牌提取成 API 密钥。官方将 App Server 定位为自建客户端的集成接口，支持认证、会话与流式事件，见 [官方说明](https://learn.chatgpt.com/docs/app-server)。

本机实际验证：Codex CLI 0.164.0，账号登录类型 chatgpt，默认可用模型 gpt-6.1-terra。程序每轮从账号可用模型中读取默认项，不硬编码账号无权使用的型号。没有安装或升级全局 Codex，没有修改全局 Agent 配置。

该接口属于实验性集成路径，本次只承诺上述本机版本的开发验收；其他 CLI 版本尚未全面验证。后续可增加独立 API 或本地模型适配器，但目前只维护这一个真实后端。

## 如何使用

1. 正常启动角色。
2. 在角色管理器点击“文字对话”。窗口会说明云端调用与额度使用。
3. 输入文字并发送。首次成功后显示“真实后端已验证”和实际模型名。
4. 点击“停止回应”停止当前轮；直接发送新一句也会取消当前旧任务。
5. “清空本次对话”清除当前进程的近期上下文与窗口内容；不重置调用限制。
6. 关闭对话窗口后不再处理聊天待办；普通启动不会自动发起模型请求。仅打开窗口也不会生成模型回应。

文字对话与 P2“内核测试”互相切换，后者仍明确是本地规则、没有 AI。真实点击与待机不请求云端模型；即使后端不可用，原桌宠仍可显示和互动。

## 可选前提与设置

基础桌宠仍可离线使用。文字对话额外需要已安装并通过 ChatGPT 登录的官方 Codex CLI。新用户请按 [官方 CLI 安装说明](https://learn.chatgpt.com/docs/cli) 和 [认证说明](https://learn.chatgpt.com/docs/auth) 操作。当前本机已经具备这些条件，不需要再安装。

程序在 PATH 中查找 Windows x64 的 codex.exe 或 npm 安装的原生程序。自定义安装位置可在启动管理器前设置进程环境变量：

```powershell
$env:LIVE2D_CODEX_PATH = 'C:\你的安装目录\codex.exe'
.\Start.cmd
```

显式路径无效时明确报错，不悄悄改用其他程序。本项目不提供密钥输入框，不要求把认证文件、令牌或密钥发到聊天或 Issue。需要重新登录时，由用户通过官方 CLI 完成，不自动登出或改写认证。

## 调用和费用边界

| 限制 | 当前行为 |
| --- | --- |
| 输入与可见输出 | 每轮输入最多 500 个字符单位；可见输出最多 500；提示词建议简短中文 |
| 请求期限 | 一个后端请求总期限 45 秒；协议单次等待 12 秒；内核总任务 60 秒，包含文字展示与清理 |
| 次数 | 每轮最多发起一个应用级请求；滚动一分钟最多 6 轮，每次程序进程最多 24 轮 |
| 重试 | 本应用不自动重试；关闭 Codex 的无限连接重试选项。CLI 内部有限连接重试由其版本实现控制，不把一个应用请求宣称为恰好一个底层 HTTP 请求 |
| 上下文 | 只发送最近三轮成功对话及本轮输入；取消或失败的回应不进入下一轮上下文 |
| 停止 | 发送中断并关闭本轮自建连接，拦截迟到文字；不操作其他 Codex 会话或进程 |
| 用量 | 有返回才累计 input/output token；停止或缺少统计的轮次标为未知；金额始终未知 |

这不是金额封顶器。已有账号的可用额度、计划与服务规则决定实际访问；不能承诺免费无限调用。客户端输出截断不等于服务端严格 token 上限，停止前已经生成的内容仍可能计入用量。

本次实测一条很短的问候仍带约 4.4k 输入 token 的 Codex 协议/提示开销，因此不按输入字数虚构费用。界面显示的发起次数属于本应用，不是完整账号账单或剩余额度。

## 数据与能力

- 聊天正文和最近三轮成功上下文只由项目保存在当前进程内，最多显示最近 20 条消息；关闭进程后不恢复，P4 长期记忆尚未实现。
- 每轮建立独立临时后端会话；必须确认 ephemeral=true 才发送对话。不复制认证令牌，不将原始后端事件或诊断管道保存为聊天日志。
- 仅发送对话文字与近期上下文，不发送模型、贴图、PSD 或原始用户日志。云端和官方 CLI 的数据处理遵循其自身设置与规则；本地清空不代表删除服务端数据。
- 对话进程使用只读约束并验证回执，关闭 shell、应用、插件、MCP、hooks、浏览器、电脑操作和多 Agent 等能力；遇到额外工具请求会拒绝并结束本轮。这些设置只用于项目启动的子进程。
- 模型输出只作为文字显示，不执行其中的命令、代码或链接，也不开放模型参数工具。本阶段身体仍只有文字与停止能力，表情/手势工作台属于后续阶段。

## 实现入口

`source/desktop-v1.1.0/app/kernel/codex-provider.mjs` 负责固定协议、认证状态、临时会话、流式增量、中断、期限和用量归一化。`chat-runtime.mjs` 负责近期上下文、限额、错误、展示节奏与内存会话。`chat-panel.html` / `.js` 提供中文窗口。

同一个事件内核在 local-test 与 codex-chat 之间切换，保留统一递增任务代次；切换会取消旧任务，避免两套内核争用身体。更新后的部署文件均列入 tools/setup.py。

## G3 基础验收

| 项目 | 结果与边界 |
| --- | --- |
| 真实后端 | 官方接口实际返回中文；多轮能回答前一轮指定的小名，未用回显冒充 |
| 流式与用量 | 独立后端首轮实际收到 15 次文字增量；取得服务返回的 token 统计 |
| 实际桌宠 | 大肥鱼上 7 项云端检查通过，包含多轮、实际生成中停止、迟到文字拦截、停止后恢复、用量、无调试端口及日志无正文 |
| 故障降级 | 以不存在的后端路径做实际失败测试；窗口明确“未完成”，角色继续出帧、无故障；真实点击仍有本地反馈，模型调用次数不增加 |
| 窗口观察 | 已观察真实中文回答、模型名、已知用量/金额未知、故障提示；管理器入口单独核对 |
| 自动回归 | 13 项 P3 Node 测试、18 项内核、2 项配置测试及 15 项 Python 测试通过；覆盖权限/临时会话拒绝、限额、超时、取消、不合作后端、错误净化等 |
| 既有模式 | 当前角色 15 项 P2 正常模式回归通过，没有增加云端调用次数 |

本次云端检查示例统计：3 个应用请求中 2 个完成、1 个中断；完成轮已知输入 8856、输出 23 token，中断轮用量未知。它是固定测试输入的实际结果，不代表其他模型、账号或未来请求的成本。

```powershell

```

只有显式运行下面命令才执行真实云端验收，会使用现有账号额度：

```powershell
python tools/acceptance_chat.py --live
```

## A01 盘点

| 环节 | 当前实现与失败处理 |
| --- | --- |
| 安装 | `Setup.ps1` → `tools/setup.py`；指定 v1.1.0 包与 SHA256，部署 PATCHES。缺包、校验不符会终止；重新部署前须退出桌宠。没有自动升级引擎。 |

| 运行版本 | 本机实际 Electron 33.4.11 / Node 20.18.3 / Chromium 130.0.6723.191；外部 Node 24 仅用于开发检查。升级运行包另行测试，不以包声明代替实际版本。 |
| 目录 | `profiles/` 注册角色；`models/` 独立模型副本；`data/<角色>/settings.json` 保存舞台设置；integration 是本机控制口令和地址；logs 是私人日志。全部不公开。 |
| 进程 | 一个管理器；舞台为 Electron 主进程及 GPU/渲染/辅助进程。正常退出等待已取得的本实例进程句柄，接口断开不单独当作退出完成。 |
| 导入 | 缺失、越界、无效 JSON 在处理前拒绝；贴图解码/写入/注册失败回滚。本进程被强杀或断电可能留下未注册副本，不自动删除不明文件。 |
| 配置 | 缺少原件但有备份可恢复；原件损坏先保留 `.corrupt-*`；两份都坏时中止并说明；未来版本不降级、不静默清空。原子替换和 fsync 降低中断风险，不承诺磁盘故障下绝不丢失。 |

## 配置恢复

1. 先正常退出桌宠和管理器。保留 `profiles/`、`models/`、`data/` 的私人备份，不要上传到 Issue。
2. 普通旧配置会补上 `schemaVersion: 1`，未知字段保留。再次保存前备份上一份有效 JSON，文件名为原名加 `.bak`。
3. 文件损坏时程序优先恢复有效备份；原件留在同目录 `.corrupt-*`，并生成 `.recovery.json`。管理器会提示该角色曾恢复过配置。不要立即删除这些文件。
4. 如果提示“没有有效备份”，请从自己备份恢复对应文件；没有备份时保留故障文件，再通过管理器重新导入模型建立独立角色。不要用空配置覆盖私人数据。
5. 如果提示“来自更新版本”，改用兼容的新程序，避免手动改小版本号绕过保护。

备份是最近一次有效保存，不是完整历史。模型副本、角色档和设置分开保存；发生断电时不承诺三个文件夹整体事务回滚。强杀留下的 `.import-*` 与未注册模型需要在所有程序退出后逐项确认，再决定是否清理。

## 复现检查

开发检查：

```powershell
python -m unittest discover -s tests -v
node --test tests/persistence.test.mjs
python tools/check_publication.py
```

先正常启动一个角色，再采样（不需要调试端口）：

```powershell
python tools/health_sample.py --seconds 1800 --interval 15
python tools/health_sample.py --seconds 28800 --interval 15
```

工具每次在私人 `validation/` 下创建独立结果目录。`samples.jsonl` 是逐次样本，`summary.json` 是当前汇总；长测达到 30 分钟后生成 `checkpoint-30min.json`。不修改系统睡眠或启动设置。测试时应保持电脑和舞台运行；休眠、退出或重启会影响结果，不能只看 elapsedSeconds 就宣布持续稳定。

结果包含采样失败数、最大采样间隔、可见状态帧停滞次数、重启次数、最后的故障计数和生命周期计数。CPU 是 Electron API 原始报告值之和，不擅自换算为整机占用。进程工作集求和可能重复计算共享页，不能当作独占内存或显存。

健康报告只取固定字段，不包含模型名称、完整文件路径、原始日志、控制口令或聊天。采样结果仍默认私人保存；公开前只整理必要统计。

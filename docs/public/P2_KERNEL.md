# P2 最小事件内核：实施与验收

更新：2026-11-23。版本：0.3.0-dev。P2 的工程实现和本机基础验收已完成，提供默认关闭的本地测试入口；不代表 AI 对话已接入，也不是正式稳定版。

项目所有者于 2026-11-23 明确要求执行 P2，因此本轮推进独立内核工程验证，同时保留 P1 未完成的休眠恢复与内存增长调查。没有把 P1 的阶段门槛改写为全部通过；整体发布仍受这些遗留项约束。

## 如何体验

1. 正常打开角色管理器，启动一个角色。
2. 点击管理器中的“内核测试”。窗口明确显示“本地测试 / 尚未接入 AI”。
3. 输入文字并发送；角色显示固定规则生成的测试文字。新输入会打断正在回应的旧输入。
4. 可试“连续点击测试 × 5”“两秒计时事件”“暂停”“免打扰”和“停止并清空待办”。开启测试时，真实角色左键点击也进入事件队列。
5. “关闭内核测试”取消当前任务、排队和定时事件；同一按钮可以再次开启。关闭窗口、重启舞台或退出程序也会结束测试。日常重新启动默认不开启测试。

暂停会取消当前任务、保留尚未执行的队列；继续后处理保留输入。停止会清空队列和定时事件。免打扰只接收文字：丢弃背景事件，而不是积累后突然播放。

这是调度工程界面，不具备语言理解、长期记忆或语音。旧桌宠待机、分区互动和手动穿戴仍由原舞台逻辑管理；本轮免打扰只管新内核事件，不宣称已经接管所有旧待机表现。

## 已实现的边界

| 部分 | 行为 |
| --- | --- |
| 事件 | 文字、点击、计时和待机；带事件编号、来源、时间、任务归属和结果 |
| 队列 | 文字 > 点击 > 计时 > 待机；小事件在固定 120ms 窗口合并，每批最多 64 个、队列最多 64 批 |
| 用户优先 | 新文字取消当前任务；满队列时先腾出背景批次；全是用户文字仍满时明确拒绝，不无界积压 |
| 单任务 | 同时只有一个活动任务；每个任务独立取消信号和递增代次 |
| 状态 | 待机、处理事件中、正在回应、已暂停、出错；出错后下一条输入可恢复 |
| 有限等待 | 任务总期限 8 秒，身体 RPC 期限 3 秒；不合作的处理器不会一直占用主任务 |
| 取消 | 覆盖排队、定时、执行中、等待中的处理器和迟到输出；只清理本内核拥有的文字，不清空手动表情/穿戴 |
| 身体隔离 | 核心没有模型参数名。适配器发送固定操作与结构化数据；不执行用户生成的代码 |
| 当前身体能力 | 只有显示文字和停止；情绪、视线、手势返回 unsupported，不假装执行。没有新增 3D 渲染器 |
| 记录 | 内存最多保留 256 条元数据；本机日志按约 1 MiB 轮转一份旧文件。不写输入或回应正文，不把事件日志当长期记忆 |

定时入口只用于 0.1–60 秒的工程验证，最多同时 16 个；不是 P7 的完整提醒或番茄钟。窗口中的本地响应逻辑只等待、显示固定格式文字并结束，不调用任何模型服务。

## 代码入口

- `app/kernel/event-kernel.mjs`：事件、单任务、状态、取消、超时；可注入时钟、处理器和身体。
- `app/kernel/contracts.d.ts`：身体协议的类型声明；当前运行代码为原生 ESM JavaScript，没有新增 TypeScript 编译步骤。
- `app/kernel/stage-adapter.mjs`：主进程到身体的固定 RPC 及期限。
- `app/kernel/body-port.mjs`：身体会话代次检查、独立文字层、真实点击入口。
- `app/kernel-panel.html` / `.js`：明确标注的本地测试窗口。
- `tools/acceptance_kernel.py`：不打开调试端口的舞台接口回归，结果默认留在私人 validation 目录。

这些 app 路径相对 `source/desktop-v1.1.0/`。内核由 Electron 主进程持有，逻辑独立于渲染器，尚未拆成后台独立进程。没有增加运行依赖或付费服务。

身体收到 taskId、generation、commandId、kind 和 payload；返回匹配编号及完成、取消、失败或不支持。begin 是受理回执，execute 目前返回应用完成回执；文字应用完成不等于用户读完。旧代次 begin/command/stop 无法覆盖新任务，停止后的同代次文字也会拒绝。

重启舞台或渲染页面开始重新加载时关闭内核并取消待办；不把旧任务送进重新创建的身体。队列不跨进程重启恢复，P4 记忆尚未开始。

## G2 验收表

| 门槛 | 证据 |
| --- | --- |
| 统一事件与结果 | 确定性测试检查事件编号、批次、任务归属和终态；真实舞台有元数据列表 |
| 合并、免打扰、用户优先 | 覆盖批次成员逐个取消、整批清理、背景满队列让位、运行中的待机被打断 |
| 状态、失败和恢复 | 覆盖暂停/继续、处理器异常、身体失败、挂起处理器期限、下一条恢复 |
| 排队/执行中/迟到取消 | 不合作处理器晚返回时不能发文字；身体端拒绝旧代次指令；真实舞台停止后没有旧文字再次出现 |
| 本地测试明确区分 | 真实窗口显示尚未接入 AI；快照 aiConnected=false；无网络模型请求 |
| 确定性回归 | 17 项内核 Node 测试通过；另有 2 项 P1 Node、15 项 Python 回归 |
| 实际舞台 | 大肥鱼和 Haru 各 15 项正常模式接口检查通过；无调试端口、无本轮舞台故障；日志不含测试输入正文 |
| 人工窗口观察 | 已观察本地测试说明、输入发送、角色上的文字、正在回应和已暂停状态；接口检查与画面证据分开记录 |

复现：

```powershell
python -m unittest discover -s tests -v
node --test tests/persistence.test.mjs tests/kernel.test.mjs
# 先正常启动一个角色；此检查会临时启用内核，结束时关闭
python tools/acceptance_kernel.py
```

超时、异常及不合作处理器的注入测试使用假时钟，避免为了测试故意卡死真实 GPU 窗口。尚未做 P2 新增代码的 8 小时回归；昨晚长测只属于 P1 版本。
